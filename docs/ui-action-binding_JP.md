# UI Actionの割当確認

UI Actionの許可リストに含まれていても、現在のキー設定に対応する本体の割当が存在するとは限りません。未割当の建築カテゴリを人工的なキーイベントとして送ると、本体の割当検索がassertを起こしてエラー画面へ移る問題を修正します。

`GameInputMapping.GetBindingEntries()`で既存の配列だけを読み、列挙値不正・未取得・未割当・割当済みを区別します。割当検索の`FindEntry`や設定の再読込・初期化を確認目的で呼びません。ToolMenuの比較とホットキー文字列取得も、未割当の検索を避けます。

`game_control domain=ui uiDomain=action action=list`は、`bindingState`と`readinessState`を分けて返します。`available`は利用可能ならtrue、既知の利用不能ならfalse、判断できなければnullです。`trigger`と管理画面のキー入力経路は共通Dispatchの直前にも再確認し、未割当・未準備・未知の場合はKeyDown/KeyUpを送りません。拒否結果には`dispatched=false`と理由を返します。直接の通常管理画面APIを使う経路に、キー割当を新しく要求するものではありません。

`dispatched=true`は入力を本体へ送ったことを示します。対象画面が期待どおり開いたことや、建築が実行されたこととは別です。許可リストへの通常建築タブや個別製品の追加は本修正の範囲外です。
