# 仮想操作の配列引数

## 修正内容

仮想`ops/*.md`の`key=value`入力で、`kinds=["items"]`や`critterTags=["Hatch"]`が配列ではなく括弧を含む一つの文字列として子ツールへ渡っていた不具合を修正する。新しい操作や書込先を追加する変更ではない。

共通parserを`WorldEditorCommandParsing.cs`へ分離した。値の先頭が引用符で囲まれていない`[`ならJSON配列として読み、`JArray`と要素の型を保持する。引用符・エスケープ・角括弧と波括弧の深さを考慮するため、一行内の空白付き配列や入れ子が別の引数へ分断されない。配列内の日付風文字列も文字列として保持する。

同じparserを使うraw ops、semantic操作、management操作へ適用する。引数を受け取る各ツールの対象選択・タグ適合・空配列の扱いは変更しない。

## 入力と互換性

以下は引数部分の例であり、単独で実行するコマンドではない。

| 入力例 | 子へ渡す値 |
| --- | --- |
| `kinds=["items"]` | 文字列一要素のJSON配列 |
| `kinds=["items", "buildings"]` | 二要素のJSON配列 |
| `tags=[]` | 空のJSON配列。受理・拒否・効果は選択した操作の既存契約に従う |
| `query="[1,2]"` | 配列風の文字列。再び配列へ変換しない |
| `payload={"domain":"info", "action":"status_check"}` | JSON構文を検証した元の文字列。既存のpayload読取側が解釈する |
| `name="Ada Lovelace"` | 空白を保持した文字列 |
| `count="7"`、`enabled="true"` | 従来どおり整数・真偽値へ推論する |
| `tags=Hatch,Drecko`、`value=1.5`、`value=null` | 従来どおり文字列。scalarの小数・null推論は追加しない |

quoted scalarは外側の引用符一組だけを除去し、内部のescape表記を原文のまま保持する。末尾のエスケープされた引用符まで削っていた境界処理を修正する。scalar全体をJSON文字列として復号する変更ではない。通常の文字列途中にある括弧、最初の`=`以降の文字、カンマ列、semanticの`->`／`=>`を維持する。

引用符なしで`[`または`{`から始まる値は構造化JSONとして検証する。その文字から始まるリテラル文字列が必要なら、値全体を引用符で囲む。JSON構文の受理範囲は利用中のNewtonsoft.Json readerに従う。複数行JSONや複数コマンドを一行へ連結する機能は追加しない。

## 構文エラーと実行制御

閉じていない引用符、括弧の不一致、解析できないJSON配列・objectは構文解析で拒否し、そのコマンドを子ツールへ渡さない。management側もpreflightで同じ解析を行う。

一つの操作編集内で実行可能なコマンドを一件に制限する既存ガードと、外側の`world_editor`要求から継承する`task`・`confirm`・`dryRun`の制御を維持する。子の指定で親の予行・確認保留を解除しない。複数編集ブロックの既存制約や部分適用契約を変更せず、一連のゲーム操作全体の原子性は保証しない。構文予行の成功を配置適合・タグ適合・実行完了の証明として扱わない。

新しい構文エラー二項目は`command_parsing.unterminated_quote`と`command_parsing.invalid_json`を用い、POのtemplate・英語・日本語・中国語の4本と、現在のruntime JSONの英語・日本語・`zh-Hans`の3言語を対応させる。POだけを追加してruntime lookupを未実装のままにする変更ではない。

これらはhostで実行した契約試験であり、ゲーム内の保存・通常UI・搬送結果まで検証した意味ではない。依存関係の取得・監査に関する実行環境上の制約と、製品の試験成否は区別する。

## nativeフィルターとの境界

本体build 744825の現行`CritterDropOff`は`CreatureDeliveryPoint`、`TreeFilterable`、`BaggableCritterCapacityTracker`を持ち、既存の動物解放地点の一覧・設定窓口で扱える構成になっている。旧prefab `CreatureDeliveryPoint`の廃止扱いを、component名の廃止や現行施設の未対応と混同しない。

通常UIのタグ変更と既存MCPのフィルター設定は、nativeの`TreeFilterable.UpdateFilters`へ到達する。容量設定も通常UIと同じ`IUserControlledCapacity.UserMaxCapacity`を使う。今回のparser修正はこの書込先を拡張しない。

`UpdateFilters`は禁止タグを除去するが、未知タグが通常UIに選択肢として存在することまでは検証しない。通常UIの項目はstorageのカテゴリと発見済み資源から作られる。したがって、未知タグが`acceptedTags`に保存された事実や`Tag.IsValid`を、通常UIの候補・適合の証明にしない。カテゴリと発見済み資源の照合、独立した`acceptedTags`再読取、通常UIの手動表示確認はそれぞれ別の証拠として記録する。

試験設備をsandboxで新設した場合、その操作は受入環境のsetupとして区別する。setupの成功を、通常建設や今回のフィルター操作APIの検証結果に含めない。

## 開発IDの実機受入

開発側build.47を導入し、同じ試験分岐・停止時刻・検索範囲で26ケース、10,864検査が成功した。

- 検索の単一・複数・空・空白付き配列が、従来scalar入力および既存coordinateのJSON payload経路と一致した。正例は現存アイテムを使い、nativeの種類・検索範囲・件数・返却内容を照合した。payloadは元のobject文字列として保持され、既存ラッパーで型付き引数へ変換された。
- 収納と動物解放地点の単一・複数・空白付き配列を、別の読取要求で得た`acceptedTags`へ照合した。収納の`[]`と`[""]`は既存consumerが拒否し、全設定を保持した。動物側はどちらも空フィルターになった。
- 未知タグは既存のTreeFilterableに保存された。既存ルールを変えていないことの観測であり、UIの候補・適合を証明しない。既知の試験タグは発見済み資源と現物カテゴリ、実在するprefab定義を照合した。通常UIの手動表示は未検証。
- 検索・収納・動物の不正JSONは、構文予行と実行要求の両方で拒否され、独立した設定を保持した。実機が子呼出数を返さない応答ではゼロと推測せず、host側のゼロ呼出試験と区別した。
- 元のフィルターと容量を独立に復元した。停止時刻・速度・カメラ・住民のID/位置/欲求・動物のID/位置・両版の設定・seed原本を保持した。動物側の`storedCreatureCount`はnativeのfilteredCountによりフィルター変更時に再集計されるため、個体の実移動と分けて記録した。

試験用の現行動物解放地点1台は許可されたsandbox分岐でのsetupに限った。通常工事・運搬・動物の実配送、全management書込の受入を示さない。別fixtureの検索正例の不在と、nativeの正常な匹数更新を試験側で不変とした条件は修正し、初回結果も保持した。本体コードを変更してそれらの試験条件へ合わせてはいない。
