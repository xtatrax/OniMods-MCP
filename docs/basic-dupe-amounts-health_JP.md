# 基本複製人間一覧の欲求値とHP

基本一覧がAmountsをコンポーネントとして探して空のオブジェクトを返す問題を修正した。既存の詳細欲求と同じ`MinionIdentity.GetAmounts().ModifierList`で読み、本体のHealthから現在HP・最大HPを取得する。対象の全ワールド範囲と識別情報・スキルは維持する。

`amounts`の表示名キーを保ち、`amountsById`で本体IDと生値を添える。表示名が衝突してもID付き一覧では別項目を保持する。`amountsEvidence`と`health`のavailable/readState/source/reasonCodesは、取得成功・部分取得・未取得を示す。availableは健康判定ではない。取得済み空集合と取得失敗を区別し、実値0を保持する。非有限値、欠損HP、不正な最大HPを0や正常値で補完しない。割合や危険度へ自動変換しない。範囲・変化率・表示値は既存の詳細欲求窓口で要求できる。

対象ハンドラーの非推奨案内は既存ローカライズキーを再利用し、ゲーム未初期化エラーとともにPO4種・実行用JSON3言語へ揃えた。

## 検証と範囲

公開作業ツリーで、実ハンドラーを連結したホスト179条件、既存Tools回帰、文言2キーのPO/JSON照合とゲームDLL参照Compileを実施した。参照Compileは警告0・エラー0。開発側では9種の不具合再導入を検出し、GetAmounts拡張メソッドの名前空間import欠落も別コピーの負例で検出した。オンライン依存監査は実行単位で省略した。

開発識別子の実機162条件で、通常・バイオニックの代表個体を詳細欲求・状態診断・医療一覧と照合し、0・生値・欠けた欲求の保持、時刻・停止・カメラ・原本・設定の保持を確認した。公開識別子を配備した変更後の実機受入は未実施。Health欠損の個体は実機で作らず、欠損と不正値の試験はホストに限定する。大人数時の応答量と任意MOD追加状態は未計測。

個別セーブ、実ID、生の応答、画像、ログ、設定は公開内容に含めない。
