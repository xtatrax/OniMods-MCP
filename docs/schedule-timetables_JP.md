# スケジュールの複数時間割

スケジュールには、24枠の時間割が複数行ある場合があります。先頭行と本体が現在使用している行は別です。読取と変更は、公開ツール `world_editor` の `/active/ops/colony.md` を通します。`colony_control` はこの経路で使う内部操作名で、外部の `tools/call` から直接呼ぶ公開ツールではありません。

この文書は経路の契約です。公開版自身の実製品ホスト、本体参照ビルド、停止中の読取・1枠変更と復元・通常UI、自然な現在行切替と元環境復帰を、それぞれ別の受入として確認しました。

## 公開窓口と下位引数

公開ツールへは、例えば次のように1操作を送ります。

```json
{
  "command": "edit",
  "path": "/active/ops/colony.md",
  "content": "<<<<<<< SEARCH\n\n=======\ncall domain=management kind=schedule action=list detail=true\n>>>>>>> REPLACE",
  "dryRun": false,
  "confirm": true,
  "task": "スケジュールの現在の時間割を読み取る"
}
```

この `confirm` は外側の操作経路を実行する確認です。`action=list` 自体は既存キャッシュの読取です。`detail=true` は下位操作の応答を保持する指定です。

以下のJSON例は、内部 `colony_control` へ渡る下位引数の構造を説明します。独立した外部ツール呼出しではありません。実際には上記の `call` 行へ対応する引数を記述し、外側の `task` と実行方針を引き継ぎます。

## 既定の読取

```json
{
  "domain": "management",
  "kind": "schedule",
  "action": "list",
  "schedule": "対象のスケジュール名",
  "task": "対象時間割の現在の行を確認する"
}
```

`schedule` を省略すると一覧を返します。指定した名前は大文字小文字を区別せず完全一致で探し、一意に決まらなければエラーにします。

既存の `blocks` は、既定で先頭24枠を返します。各枠の `hour` は行内の0～23です。現在の行へ暗黙に切り替えません。既定の応答に全時間割を追加せず、必要な分だけ取得できます。

各スケジュールには、次の小さな情報を追加します。

| フィールド | 意味 |
| --- | --- |
| `blocksScope` | 既定の先頭行か、明示選択した行か |
| `blocksTimetableIndex` | `blocks` として返した行の0始まりの番号 |
| `totalBlockCount` | 本体の既存の枠数 |
| `timetableCount` | 24枠を1行とした本体の行数 |
| `currentTimetableIndex` | 本体が現在使用している行の番号 |
| `currentBlockIndex` | 全行を通した本体の現在の枠番号 |
| `currentGroup` | 現在の枠の本体グループID |
| `unavailableFields` | 取得できなかったフィールドと理由 |

`currentHour` は一覧全体の現在時刻です。`assigned` は既存の割当参照から読み取った名前、`groups` のIDや名前は本体の既存定義です。

取得できない値を0や空配列へ補完しません。未知のメタデータは明示的な `null` と理由を返し、取得できた実値の0と区別します。実際に空の割当リストだけが `[]` です。枠数が24の倍数でない場合や現在の行・枠が範囲外の場合も、正常な行として扱いません。

## 行を選ぶ・全行を取得する

`list` に `timetableIndex` を追加すると、その行の24枠を `blocks` として返します。番号は0始まりです。この指定は読取対象を選ぶだけで、本体の現在の行を変更しません。

全行が必要な場合だけ、`includeTimetables=true` を指定します。各行の番号と24枠を `timetables` に追加します。通常の `blocks` は、同時に選択した行を保持します。

```json
{
  "domain": "management",
  "kind": "schedule",
  "action": "list",
  "schedule": "対象のスケジュール名",
  "timetableIndex": 1,
  "includeTimetables": true,
  "task": "明示した時間割と全体の構成を確認する"
}
```

## 1枠を予行・変更する

`set_block` は `timetableIndex` と行内の `hour` を受け取り、絶対枠番号を `timetableIndex * 24 + hour` として特定します。`timetableIndex` を省略した場合は従来どおり先頭行です。`group` には `list` の本体グループIDを使用します。

```json
{
  "domain": "management",
  "kind": "schedule",
  "action": "set_block",
  "schedule": "対象のスケジュール名",
  "timetableIndex": 1,
  "hour": 12,
  "group": "Hygene",
  "dryRun": true,
  "task": "指定した行の1枠を変更する前に確認する"
}
```

予行と実行には、外側の操作経路と下位ハンドラーの2つの境界があります。

- 外側の `world_editor dryRun=true` は構文・操作範囲を予行し、下位ハンドラーを呼びません。対象の現在値や本体側の変更可否を検証した証拠にはしません。
- 外側を実行しても、`call` 行が `dryRun=true` または `confirm=false` の場合は操作経路が下位呼出しを省略し、予行として返します。
- 新しい下位 `set_block` ハンドラー自身も `dryRun=true` で本体の変更・通知を呼ばない保護を持ちます。この保護を下位ハンドラーまで到達させる通常の公開経路は現時点でなく、直接のホスト試験と公開経路の実機予行を分けて検証します。新しい反射呼出しや迂回経路は使いません。

実行する場合は、外側の `dryRun=false`、`confirm=true`、空でない `task` が必要です。下位で明示的に拒否した確認を、外側が上書きすることはありません。実行前は `list` で対象行と既存値を読み、外側の予行とは別に確認します。名前の曖昧一致、不正な型、範囲外の行・時刻、許容しない強制フラグや別の対象選択は拒否します。

変更には通常UIの塗り操作と同じ本体コントローラー `Schedule.SetBlockGroup` を1回だけ使います。通知や割当先への反映は本体に委ねます。すでに同じグループであれば、本体の呼出しも通知も行いません。ポインターでの塗り操作そのものを再現する窓口ではありません。

実行された下位ハンドラーの応答では、呼出しと観測結果を分けます。外側だけの予行や、下位呼出しを省略した予行は別の応答です。

| 状態 | `nativeInvoked` | `applied` | `changed` / `requestedStateObserved` |
| --- | --- | --- | --- |
| 予行・呼出し前の拒否 | `false` | 整数 `0` | `false` |
| 同じグループのため変更不要 | `false` | 整数 `0` | `false` / `true` |
| 本体呼出し後に指定した値を確認 | `true` | 整数 `1` | `true` |
| 呼出し後の所有者変更・再読取失敗 | `true` | フィールドを省略 | `null` |

下位応答の `applied` は変更枠数の整数カウンターです。外側の応答にも集計値があるため、`results[].result` と `nativeOutcome` の対象を区別します。呼出し後の不明な数を0へ置き換えません。`accepted` は要求または本体呼出しの受理を示し、`nativeInvoked` とは別です。本体呼出しが例外で中断した場合は `null` です。`status=partial` は完了の保証ではありません。操作は自動で再試行せず、次の判断の前に状態を読み直してください。

## 読取と既存操作の範囲

新しい `list` と `set_block` は、準備済みの本体データだけを読みます。固定した型・フィールドの `Db._Instance` と `Schedule.assigned` を検証し、キャッシュ未準備・型不一致・部分的な割当参照は取得不能として返します。`Db.Get()` や、未作成の割当リストを生成する `GetAssigned()` はこの経路では使いません。既存参照の解決には本体の `Ref.Get()` を使い、その内部キャッシュの更新までは無書込と保証しません。

ゲーム、本体マネージャー、定義・一覧キャッシュの所有者と参照を確認し、変更後は対象枠と割当先を再読取します。同一フレームの原子的読取や、あらゆるフィールド変更の事前検出、複数スケジュールをまたぐ割当の一意性を保証するものではありません。

`create`、`assign_dupe`、`optimize` とそれらが使う旧変換処理は、この変更では従来のままです。新しい行指定・無変更予行・欠測の契約を、それらの操作へ拡張したとは扱いません。グループ名・割当名は本体の言語を使用し、MCP独自の説明文はMCP側のローカライズ設定を使用します。

## 検証済みの限定範囲

公開版自身の実製品全文ホストと本体参照ビルドを確認しました。欠測null／真0／不完全状態の詳細な境界はhostの根拠とし、実機で全てを再生成したとは扱いません。旧ハンドラー全文もコンパイルでき、直接の無変更予行でnative変更を行う意味的な負対照は失敗します。停止した試験環境で、既定24枠と明示した全行・行指定、既知の空割当と索引0、不正指定の拒否、外側予行と下位skip、同値no-opを区別しました。

通常UIと同じ本体コントローラーで非先頭行の1枠だけを変更し、全他枠・他表・割当・alarmを保持して、その1枠を元へ戻しました。変更前・変更後・復元後と通常閉鎖後の実画像を別々に確認しています。下位handlerへの直接dryRun／通知回数はhostの範囲で、公開outerpreviewによる同じ証明とは扱いません。

別の自然進行窓では、本体の現在行・索引の切替を独立した個体currentblockと通常UIの境界前後画像へ照合しました。全時間表・割当・alarmの保持と安全観測、元の停止セーブ・速度・カメラへの復帰、通常終了とゲーム未起動、許可した自動保存関係の所有treeと元の導入物・設定・保護セーブ・既存画像への復帰を確認しました。受付だけでUI成功を判断せず、画面不在だった回は成功に含めていません。

個体detailにないmodel情報、通常排出・漏出、全不足／危険とHUDの整合、全表・全DLC・他MODの全組合せやポインターpaint自体の再現には一般化しません。管理画面要求の送信と実表示の観測を分ける追加修正は、この受入では実装・検証していません。個別の保存先・対象ID・設定値・生応答・私有補助と開発履歴は含めません。
