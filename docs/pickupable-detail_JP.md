# セルMarkdownの落下物詳細

`/active/map/cell_X_Y.md` の「落下物の概要」部分は、MCPの文言言語で概要・件数・明細・集計・元素の6ラベルを返します。名前・Prefab ID・元素IDはゲームの取得値を保ちます。人間用全体マップのJavaScript詳細パネルとは別の読取経路です。

## 質量と欠測

PrimaryElementがない個体の質量は未取得として表示し、0 kgへ補いません。実際に取得した0は従来どおり `0.00 kg` です。全件未取得なら合計も未取得、取得済みと未取得が混じるなら「既知分のkg＋未取得の件数」とし、総質量が確定したようには表示しません。個体・グループ・全体の3段階で同じ規則を使います。既知の値の小数2桁とkg、既存の質量順と同値の順序を保ちます。

対象はcachedCellまたはオブジェクト位置がそのセルに一致するPickupableです。収納状態と両方のセル値を明細に残します。表示上限は既定8で、集計の総件数・総質量は表示行数で切り捨てません。空セルではこの部分を省略します。この変更は収納・分類・可視範囲・通常のセル読取の許可を変更しません。

## 原本と実行時

`Localization/po/` のテンプレートと3言語を原本とし、現在の実行時は `Catalogs/cell-details.{en,ja,zh-Hans}.json` を使います。既存6ラベルと新規 `cell.pickups.mass_unavailable`、`cell.pickups.mass_partial` の8キーを維持し、`scripts/verify_pickupable_detail_localization.py` で対応とplaceholderを検査します。暫定Hantと既存Hansは分け、Hans訳はPOの `Runtime zh-Hans msgstr` 注記に保持します。ゲームの言語は変更しません。

## 検証の境界

ホスト回帰は実際の詳細生成ソース全体を読み、欠測・既知0・混在・グループ・上限・収納・対象セル・3言語・非破壊読取を検査します。変更前ソース全体へ差し替えた負試験で、欠測を0へ補う挙動が失敗することを別に確認します。ホスト試験、本体DLL参照ビルド、導入DLLによる実機の読取は別々の証拠です。

この範囲は有限な既知質量およびPrimaryElementの欠測です。NaN/Infinity、他のJSONや後段の別サマリーの欠測、分類・cachedCellと位置のずれ、全体マップの実ピクセル一致までを解決した契約ではありません。

開発版・公開版それぞれ自身のDLLで、可視の現物ありセルを停止状態のまま読み、MCP文言3言語の6ラベル、ゲームの名前・ID、個体・グループ・合計のkg表示を検索の取得値と照合しました。記録セルと実位置セルが一致する通常個体を使い、収納中と未収納を含む既知の有限質量を確認しました。全体マップの既存61キーと描画ソースを保持し、既存3言語VM検査も通しています。

PrimaryElement欠測・既知0・混在は両版の実ソース54条件で確認しており、実機でその個体を観測したという証拠ではありません。両版の参照ビルドと変更前全文への負試験も通しました。ゲーム言語・地形・カメラ・ワールド・領域登録・保存・シミュレーション進行を変更せず、MCP文言を元へ戻し、通常終了後に元の導入物・設定・既存画像と未起動状態へ復帰しました。公開版は専用設定とパッチ所有者を確認し、開発版の成功を代用していません。
