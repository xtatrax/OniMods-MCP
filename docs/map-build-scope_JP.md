# 地図建設差分の要求範囲

## 契約

地図のSEARCH/REPLACEで変更したセルから生成する`anchors`は、明示的な配置集合として扱う。親のviewport矩形・相対区域・検索・経路指定で拡大せず、離れたアンカー間を自動補間しない。複数セル設備はネイティブの占有形状からアンカーを解決する。区域のworldを先に確定し、生成済みの絶対座標を再び相対変換しない。

`build_area`に`anchors`プロパティがある場合、空・null・配列以外を拒否する。不正な各要素も既存の座標検証で拒否し、別の矩形や検索指定へ切り替えない。アンカー未指定時の明示`points`・矩形・検索による経路解決と、直接の`auto_connect`は維持する。

確認・予行・素材・向き・world・施工予算・地形変更への明示許可は保持する。設備自身の既定自動配線など、別途許可された付帯経路まで無効にする変更ではない。

## 受入範囲の限界

通常設計図の予約と範囲保持の試験であり、工事の完了、隣接との物理接続、給電・実流量、従来自動接続全体の通常UI委譲を証明しない。明示経路の互換性と不正anchorsの全入力組合せはホスト試験の範囲。地図のdryRunは構文・占有形状の予行であり、配置適合・付帯経路を検証した意味にはしない。TODOの予行全般とレイヤー別操作計画は未完了のまま残す。

公開側ソースから作成したbuild.7を公開固有ID・専用設定で読み込んだ。開発版と同じ通常設計図4ケースが成功し、指定した電線6個とR90ドア1個、全占有8セルを独立したcell_infoで照合した。公開側へ開発用layer-snapshot機能を追加せず、既存の正式coordinate読取で周囲77セルを毎回取得した。既設物体のID・位置・形状、自然固体、住民のID・位置・欲求、採掘指示と停止時刻を保持し、合計3657検査が成功した。

公開側の434条件・1100条件のホスト回帰と、公開IDのReleaseビルドも成功した。公開側には開発専用の予行メタデータがないため、試験もその追加を要求せず「配置検証済みと称していないこと」と子操作ゼロを確認する。今回の差分は要求範囲の修正に限定する。

原本セーブ、両版の設定、無効な開発DLLと他MODの保持を配備後に照合した。個別セーブ・ID・座標・生応答・スクリーンショット・ログ・設定は公開側へ含めない。元の開発版build.45・導入物・設定・MOD選択・原本セーブへ復帰し、43検査と通常画面で確認した。停止時刻・選択速度・カメラ・住民の状態を保持し、試験予約は元セーブへ持ち込んでいない。新規ログのException行は0で、既存のWarningはある。
