# 間欠泉の分析状態と現物詳細

現物詳細の `work` に、本体の `Studyable.Studied` を読み取る欄を追加しました。分析済み状態と作業進捗を別々に返し、進捗が初期値だからという理由で未分析とは判定しません。

## 読取経路

`world_editor command=read path=/active/objects/details.oni` で、取得済みの現物 `id` と `worldId`、必要な `section=status|properties|work` を指定します。`id` と定義の `prefabId` は別の識別子です。各区分は同じ現物候補の選択・露出条件を使います。

- `status`: 本体の登録済みステータス一覧。分析済みの表示は、登録されている `Studied` などのnative IDで確認します。表示名・説明はゲーム側の言語を維持します。
- `properties`: 現物の質量・温度・素材など、既存の物性情報。
- `work`: 既存のWorkable値に加え、対象が `Studyable` のときだけ分析状態を返します。

この変更は分析開始・即時完了の新しい操作窓口を追加するものではありません。読取で分析状態を書き換えたり、作業の開始・完了やUI更新を要求したりしません。

## workの追加項目

| 項目 | 意味 |
| --- | --- |
| `studied` | 本体getterで得た `true` / `false`。取得できなければ `null` |
| `studyStatus` | getter取得済みは `observed`、取得できなければ `unavailable` |
| `studySource` | 取得元 `Studyable.Studied` |

getterで例外が発生した場合は `studied=null` と `studyStatus=unavailable` を保ち、その現物の `unavailableFields` に `Studyable.Studied` を追加します。未取得を `false` や正常値へ補いません。`Studyable` 以外の通常Workableには、この分析専用の3項目を追加しません。

`workSeconds` / `remainingSeconds` / `percentComplete` と `numericState` は既存の数値観測です。分析済みを示すために書き換えません。例えば `remainingSeconds` が総作業時間と同じで `percentComplete=0` でも、それだけでは `studied=false` と判断できません。分析状態は取得済みのgetter値、未取得ならその欠測として扱います。

## 間欠泉の露出条件

間欠泉の候補は、有効セル・本体の可視情報・`Uncoverable.IsUncovered` を確認します。間欠泉専用レジストリーからの列挙だけでなく、他の現物レジストリーから同じGeyserへ到達する場合も、候補統合後に同じ露出条件を適用します。

この追加条件は、実際に `Geyser` コンポーネントを持つ現物にだけ適用します。通常設備・植物など、非Geyser候補の選択規則を一律に厳しくする変更ではありません。条件を満たさない対象を、現物ID指定によって新たに公開することもありません。

異なる読取窓口のID・Prefab・world・座標が一致する比較と、native GameObject参照そのものの独立照合は区別します。別窓口の一覧から消えたことだけで、埋没や非表示の理由を断定しません。

## 確認した範囲と残る境界

停止中の開発版・公開版それぞれの初回・通常再ロード試験では、同じ露出済み現物の `status` / `properties` / `work` を照合しました。既存の本体デバッグUI経路への明示要求後、`work.studied` が `false` から `true` となり、ステータス一覧にnative ID `Studied` が現れました。数値の `workSeconds` / `remainingSeconds` / `percentComplete` は初期値のまま維持され、分析済み状態と進捗の初期値が共存することを確認しました。

この試験は、許可された既存の一時的なInstantBuild経路を使ったものです。サンドボックスモードの切替は要求していません。本体のデバッグ分岐は既存choreの取消、イベント通知、`Refresh` を行い得るため、単一フィールドだけを変更したとは主張しません。返却されたボタン要求結果と状態変化を確認したもので、マウスクリックの独立観測や、複製人間による通常作業の完了を証明するものではありません。

次の境界はホスト試験・一次ソースの根拠までで、今回の実機受入へ含めません。

- getterが取得不能になる実例と、その実HTTP応答。
- 埋没または非表示の間欠泉を、実機で除外する反例。
- 複数レジストリーに重複登録されたGeyserの実体経路。
- 複製人間の通常分析完了による進捗再初期化と、その一連の遷移。

通常Workableの既存欄と、間欠泉の候補統合後の露出条件はソース・ホストでも照合します。これらを、全セーブ・全DLC・全MOD構成や全native getterの実機確認へ一般化しません。残る境界を含む親課題は未完了です。

両版の実ソースを使うホスト試験では、新規36条件と既存回帰群を確認しました。旧reader全文または旧候補選択全文への差替えはコンパイル後に新条件で失敗し、修正差分への感度を確認しています。本体DLLを参照する両版のビルドは警告・エラー0件でした。実機4窓の各32条件を受入れ、保存・時間進行・撮影を要求せず、試験後は元の導入物・設定・原本選択先と開始時の未起動状態へ復帰して照合しました。ホストの代替入力と実機で観測した状態は分けて扱います。
