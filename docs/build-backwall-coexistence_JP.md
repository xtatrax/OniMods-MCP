# 通常の前景設備と完成背景壁の占有を区別する

対象設備の本体定義が `ObjectLayer.Building / TileLayer.NumLayers / BuildLocationRule.OnFloor` の場合に限り、完成済み `ObjectLayer.Backwall / TileLayer.NumLayers` との座標の重なりを、汎用の設備障害から除外する。Prefab名による特例は追加せず、前景と背景の本体レイヤーを区別する。

背景壁の設計図、同レイヤーの設備、対象が背景壁・タイル・特殊配置ルールの場合、補助TileLayer付きや定義欠測は従来の判定へ残す。地形・植物・支持・可視性・ワールド・utility／bridge／logic端点、実行直前の再検査と即時完成側の独立した背景壁保護を維持する。既存設備の形状が欠測した場合に元から列挙されない問題は、この修正の対象外である。

完成設備を指定した予行は、その設備の本体参照セルを新しい設備のアンカーに使い、占有範囲の左下へ自動補正しない。位置解決の詳細は[予行の完成設備指定](build-preview-id-anchor_JP.md)に従う。従来の名前検索や施工窓口は変更せず、名前検索の全走査や全予行の非変更を証明するものではない。

## 検証した範囲

開発版・公開版それぞれ自身の製品ソースを使うホスト665条件と本体DLL参照ビルドを確認した。各版自身の旧障害判定の全文へ差し替えた負対照はコンパイルに成功し、完成背景壁との共存の正例で失敗する。ホストでは本体形状・支持・素材・UI入力等の一部を境界で代替しており、この結果だけで実機の配置許可を証明しない。

停止実機の試験では、許可されたサンドボックスで支持床と完成背景壁を即時設置する工程を準備として分離する。その後に本体の `sandboxModeActive=false` を読み取り、通常モードのMCP予行と既存の通常配置窓口を照合する。即時設置を通常配置の成功例へ数えない。

開発版・公開版それぞれ自身の停止実機で、通常モードの予行と、本体の6セル占有に対応する実際の `Constructable` 予約を確認した。完成済みの背景壁と支持床が保持され、ゲーム時刻と取得できるカメラ情報も変わらなかった。公開版固有の設定先と所有パッチIDも独立して照合した。

両版とも試験設備を保存せず元セーブへ戻り、通常終了後の導入物・設定・保護セーブ・既存画像と未起動状態への復帰を確認した。開発版の結果を公開版の実機受入へ代用していない。

## 残る限界

予約の確認は、作業員による搬入・施工・完成や完成後の稼働を確認した意味ではない。通常実行の既存経路は `BuildingDef.TryPlace` であり、`BuildTool` の選択・入力操作は別途未確認である。全回転・特殊設備・DLCや他MODの全組合せ、予行・一時UI・通常ルールのスコープを含む本体全状態の不変も受入範囲へ含めない。新しい評価経路、壁の除去、強制配置で未検証部分を補わない。

個別のセーブ、対象識別子・座標・時刻、設定値、生応答、画像、試験補助、本体DLLおよび開発履歴は公開差分へ含めない。
