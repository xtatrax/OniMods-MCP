# ロードしたセーブの保存 MOD ラベル

`game_control domain=save action=status` は、通常のネイティブロードで観測した MOD ラベルのコピーを返します。
ファイル上の MOD 一覧や、現在有効な MOD の一覧をその場で再取得する操作ではありません。

観測元は、`SaveLoader.Load(IReader)` が `MatchFootprint` へ渡す `SaveFileRoot.active_mods` です。
旧形式のセーブでは、この地点より前にネイティブ処理が `requiredMods` を変換する場合があります。
したがって、結果はネイティブロード後のラベルであり、すべての旧セーブの生データをそのまま示すものではありません。
各ラベルの `id` は `KMod.Label.id` です。MOD の `staticID` とは別の値として扱ってください。

フックは、対象メソッド・フィールド・引数マスクと一意な呼び出し箇所を確認して導入します。
未知または曖昧な形では観測を無効にし、元のネイティブ命令列を維持します。
コピーを公開するには、同じロードで一つの本体呼び出しと一つの観測があり、内側・外側の両方が成功する必要があります。
ロードの入れ子、順序違反、例外、失敗結果では旧データを公開しません。
新しいロード試行を始めると前のコピーは破棄され、失敗後に復活することはありません。

コピーは、成功した内側ロードの終了時に取得した `Game` の弱参照と、そのロードを行った `SaveLoader` に結び付けています。
外側ロードの終了時にも同じ所有対象か確認します。ロード開始前から `Game` が存在することは要求しません。
メニュー、ロード中、準備未完了、所有オブジェクトの不一致では利用不可になります。
他 MOD による任意の命令書き換えや、任意スレッドでの同時ロード全般を保証する仕組みではありません。

`available=true` のとき、`total` は捕捉したラベルの総数です。
`matched` は検索一致数、`returned` は実際の返却数、`savedLabels` は返したラベルの配列です。
ラベルには元の順序の `index`、`id`、`title`、`version`、配布元の名前と数値を含みます。
重複や null の文字列を別の ID や既定値へ置き換えません。
既知の空リスト・検索一致ゼロは、利用不可とは区別します。利用不可では件数と配列は null です。

返却件数は既定 20、最大 100 です。検索は ID とタイトルに対する大文字小文字を区別しない部分一致です。
検索を先に適用し、件数上限で省略した場合は `truncated=true` を返します。
検索語は前後の空白を除去した後で最大 2048 UTF-16 コード単位です。
捕捉できるラベルは最大 256 件、各 ID・タイトルは最大 2048 UTF-16 コード単位です。
捕捉上限を超えると、切り詰めたリストを既知の結果として返しません。

`source` は観測箇所、`loadedSourceFilename` は実際にロードへ渡されたファイル名です。
`activeSaveAtLoad` は成功時の active save、`activeSaveFile` は読み取り時の active save です。
自動セーブの正規化で両者が異なる場合や、別名保存で active save が変わる場合があります。
`activeSaveChangedSinceLoad` は読み取り時と成功時の active save の差を示します。
active save が変わっても、元のロード元ファイルや保存ラベルを新しいファイルのものに読み替えません。

`includeSaveContext=true` を指定したときだけ、`currentSaveContext` を追加します。既定の false や省略時には追加のワールド読取を行いません。
この欄は、読取時点の本体キャッシュにあるコロニー名、ワールドの ID、発見・モジュール内部フラグなどです。
ロード時に捕捉した保存 MOD ラベルとは別の情報であり、保存ファイル内のコロニーやワールドの値として扱わないでください。

名前を読むのは、ネイティブの `IsDiscovered` が true で、`IsModuleInterior` が false のワールドだけです。
それ以外の行も ID とフラグは残しますが、名前用のコンポーネント検索を行わず、`clusterNameAvailable=false`、名前と名前の取得元を null にします。
対象となる行でも、ネイティブ保存処理と同じ基底コンポーネント検索を使い、実際の型が `AsteroidGridEntity` の場合だけ既存の名前を読みます。
未対応の型やコンポーネント欠測では別名を補わず、UI 表示名や別のコンポーネントへ置き換えません。取得した文字列自体が null の場合もそのまま返します。
発見フラグは本体のデバッグ開示を含む `IsDiscovered` の結果であり、内部の発見済みフィールドだけを示すものではありません。

追加欄は最大 128 ワールド、各名称は最大 2048 UTF-16 コード単位です。
取得不能や上限超過では、この欄の `worldCount` と `worlds` を null にします。既知の空リストは 0 と空配列で区別します。
追加欄だけが未取得になっても、既に捕捉できている保存 MOD ラベルを空や未取得へ変更しません。
ワールド選択、発見状態の変更、名前の整形、レポート・統計処理、キャッシュの初期化や更新は行いません。

status の読み取りは保存ファイルを開かず、ロード、保存、`MatchFootprint` の再評価を実行しません。
保存を変更しただけでは、その新しいファイルの保存 MOD を観測したことにはなりません。
新しい保存ファイルの確認には、通常のネイティブロードが別途必要です。

実ソースを接続したホスト試験では、ロード成功と所有対象、欠測と既知の空リスト、上限、名前の取得制限などを確認しています。
以前の実装全体に差し替える対照では、コンパイル後に新しい条件の検査が失敗することを確認しました。
これはネイティブロード順序や保存ファイルの実機検証とは別の根拠です。

開発版と公開版それぞれで、未ロード時の未取得、通常ロード後の保存ラベル、検索・件数上限・反復読取、追加情報の既定省略と名前の取得制限を確認しました。通常の別名保存と再ロードにより各版のラベルを照合し、現在有効な MOD 一覧との混同や他の保存ラベルの消失がないことを確認した限定範囲です。読取と保存ではゲーム内時刻・速度・停止状態を保持しました。

試験後は元セーブを停止状態で選び直して通常終了し、控えた導入物・設定・共有保存要約を復元しました。原本と既存保存データ・画像を保持し、新しい試験分岐を残しています。本体が通常処理で保存する採番値へ直接書き戻していません。PLib の全設定項目、すべてのセーブ形式・他 MOD 組合せ・未知の命令列を検証したものではありません。
