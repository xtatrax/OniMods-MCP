# セルの登録と設備定義上の占有

セル情報の `objectsByLayer` と `utilities` は、問い合わせたセルの native `Grid.Objects` 登録を返す窓口です。設備の登録があることと、そのセルが設備定義上の占有形状に入ることは、同じ意味とは限りません。

## 追加する関係値

これら2窓口の既存行で `Building` を持つ実体にだけ `selectedCellRelation` を追加します。

| 値 | 読み取った意味 |
| --- | --- |
| `occupied` | 取得済みの native 占有セル集合に問い合わせセルが含まれる |
| `registered_only` | native 登録はあるが、取得済みの定義上占有セル集合には含まれない |
| `geometry_unavailable` | 占有形状を取得できず、内外を判別していない |

`bounds` の矩形を埋めて判定せず、既存 `NativeBuildingFootprint.Contains` の正確なセル集合を使います。形状欠測を `registered_only` や「空いている」へ補いません。既存の `geometryAvailable`、`geometryError`、`occupiedCells` 等の情報も保持します。

非Buildingの登録行や、既存の `buildings` / `blueprints` / `pickupables` / `dupes` / `plants` 一覧にはこの項目を追加しません。これら別の取得範囲を、新しい登録窓口へ変更するものではありません。

## ポンプの追加登録

確認した本体の手押しポンプは通常の2×4設備定義と別に、取水深度に応じた下側の2列を `PumpingStationGuide.OccupyArea` から同じGameObjectとして登録します。これは本体の処理であり、追加登録が見えたという理由で設備定義の形状を尾管まで広げません。

`registered_only` は通行・衝突・建設・解体・取水可否を判定する値ではありません。追加登録も本体の別ルールで使われ得ます。設備の表示名・ID・座標や原点／左下アンカーと、問い合わせた `selectedCell` を区別してください。

## 変更しない処理と検証の境界

既存行のID・座標・形状・原点・アンカー・状態と取得順を保ち、すでに取得した形状から関係値だけを付記します。形状計算、物理占有インデックス、他の地図、配置・解体処理、登録内容、本体UIやsimulationの状態は変更しません。native getterの追加や欠測の独自推測も行いません。

この小さな表示追加に、同じ条件式を書き写す新しいホストは作りません。既存の形状ホストがあることを、新しい行生成の実行証拠とは扱いません。ソース上の保持・本体参照ビルド・各IDでの実機観測は分けて記録します。欠測・疎な形状・全設備や描画UIの受入は、実際に観測した条件だけに限定します。

## 限定した実機受入

開発版 `0.2.5+build.93` と公開版 `0.2.5+build.33` は、それぞれ自身のソースを本体参照でビルドし、警告0・エラー0でした。raw2呼出しの明示指定・既定false・関係値の付記を除くソース全体の一致を確認しています。新ホストの成功や、対象外の既存ホストを新しい行生成の実行証拠に加えてはいません。

両IDの初回ロード・通常再読込の計4回で、同じポンプと最大18セルを固定して受入れました。本体定義の占有8セルと、同じポンプの取水部の追加登録8セルを別々に照合し、後者は物理占有インデックスの `buildings` 一覧には入りません。通常の電線・液体管でも両raw窓口の全行が一致し、既存の非raw一覧行には関係値を追加していません。延べslot行数と設備の固有件数は区別しています。

4回の業務読取は計97回で、初期化と初期化完了通知の8呼出しを別に記録しています。同一ケースの完全な形状と、対象となるraw／非rawのObjectInfo行を、項目除外や採番の正規化を行わず比較しました。セル環境・既存connectionSummary等の影響外情報は比較範囲の外であることを試験前に定め、生応答全体は私用証跡に保持しています。変更前DLLの生応答との完全比較ではありません。

全6項目の停止時計と保護セーブの内容を保ち、新規保存・進行・建設・解体や、登録を直接書き換える操作は行っていません。公開切替のMOD不一致は既存の本体UI確定経路を使い、閉鎖と停止維持を確認しました。試験後は開始時の未起動状態と控えた導入物・設定・保存先選択・他MOD・DLCへ復帰し、起動に伴うセッション番号の増加を区別しています。

今回の実機範囲には非Buildingのraw行、形状未取得のraw行、疎な占有形状はありません。これらの新しい行生成はソース境界の確認であり、実機で故障状態を作って検証したとはしません。ブリッジ端点との追加比較、通常UIの描画、通行・配置・解体・取水の実挙動は受入に含めていません。
