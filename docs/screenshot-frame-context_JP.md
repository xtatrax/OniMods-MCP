# スクリーンショットと撮影フレーム情報

通常撮影、レイヤー切替後の撮影、座標付き撮影は同じ有限キューを使う。呼出元の同期処理は描画を待たずに要求を受理し、完成結果を別に読む。

```json
{"domain":"camera","action":"screenshot","waitFrames":2}
```

返された `requestId` で `navigation_control domain=camera action=screenshot_status requestId=...` を確認する。`world_editor command=camera action=screenshot_status` も同じ結果へ委譲する。`world_editor command=screenshot` の各 `captures` にも個別の要求ID・状態・画像のパス／URLを保持する。複数レイヤーの画像はそれぞれ別のフレームになる。

## 受理と完成

- `queued`／`running`: 未完成。PNGのパス、既存ファイルの存在、`readyAfterFrames`、`latestUrl` を完成の証明にしない。
- `complete`: この要求の撮影処理が終わった。画像を要求した場合は、PNGのエンコードと同じディレクトリでの置換／移動が成功してからこの状態になる。
- `failed`: 未ロード、ゲーム／シーン変更、カメラ消失、期限切れ、読取／保存失敗など。`error.code` と翻訳済み説明を返す。後続の要求を停止したままにしない。
- `unknown`: このプロセスに保持された要求ではない、または有限履歴から除かれた。未撮影や成功とは判定しない。

PNGを読む条件は `status=complete` と `imageState=verified`。`image` のSHA-256・バイト数・画像サイズが、この要求で生成した画像を識別する。状態取得時に現在のファイルを照合し、削除や同名上書きがあれば `missing`／`changed`、読めなければ `read_failed` として `imageAvailable=false` を返す。撮影時の完成記録自体を書き換えない。`latestUrl` は可変であり、要求を識別するURLではない。

撮影を要求しないレイヤー切替の `complete` は切替処理の完了で、画像状態は `not_requested`。失敗の直前に保存まで進んでいた場合も、存在するファイルだけで成功を補わない。

## 予約時と撮影時

`requested` は予約時のカメラ／時刻と指定内容。互換用の `cycle`／`screen`／`camera`／`viewport` も予約時の値で、タイミングを明示する。`readyAfterFrames` は当該要求の待機設定から作る目安であり、先行要求・描画停止・処理時間を含めた期限ではない。

`captured` は `WaitForEndOfFrame` 後の同じメインスレッド区間で取得する。PNG用テクスチャの取得とカメラ情報の観測の間に `yield` を置かず、`Time.frameCount` が同じことも確認する。

- `frame`／UTC／unscaled実時間と、取得できたゲーム時計・サイクル。
- 実際の `Camera.main` の位置・回転・投影方式・倍率・アスペクト比・投影行列・pixelRect。コントローラー位置は別項目。
- 画面サイズ、アクティブworld、実際のレイヤーの生ID、シーン番号・名前。レイヤーの既存ビュー名はネイティブID同士の比較で取得し、未知の表示を `none` へ補わず `viewAvailable=false` とする。生IDのハッシュ文字列を表示名と取り違えない。
- カメラからワールド平面へ投影した四隅と、グリッド内に丸めた概算のセル境界。

PNGはGUIや他のカメラも含む合成画面であり、`Camera.main` の情報だけから画面全体の描画内容を保証しない。概算境界は霧の発見済み範囲やUIに遮られていないセルの一覧ではない。時計・world・レイヤー・投影の欠測はavailability／null／reasonを保持し、`contextComplete=false` とする。欠測をサイクル0・レイヤーなし・空の可視範囲へ置き換えない。

遅延中にカメラやレイヤーが変わった場合、実際の撮影時情報を返す。指定world／レイヤーとの一致は別の比較値で示し、要求に合わせるために撮影直前のゲーム状態を勝手に作り直さない。座標グリッドの指定内容も `requested_configuration` であり、実際の描画確認にはPNGを使う。

## 保持と失敗時の継続

未完了要求は最大16、終端履歴は最大64。同時に待機している同名ファイルは拒否し、撮影待ちのファイルを既存の自動整理から保護する。保存時は要求ID付きの一時ファイルから確定し、その要求が作った一時ファイルだけを後始末する。終端履歴の数は画像保持数とは別で、既存の画像整理設定は維持する。

予約から60秒のunscaled期限を設け、通常Updateが進む状態なら描画待ちの要求も失敗へ進める。無効化・破棄時も未完了要求を失敗にし、古いコルーチンが後から完成を書けないように所有権を確認する。UnityのUpdate自体が停止した場合の即時応答は保証せず、メインスレッドを同期待機する回避策は使わない。

## 根拠と検証範囲

導入されたUnityの公開API署名を静的に確認した。描画後に取得するタイミングは[UnityのCaptureScreenshotAsTexture](https://docs.unity3d.com/ScriptReference/ScreenCapture.CaptureScreenshotAsTexture.html)と[WaitForEndOfFrame](https://docs.unity3d.com/ScriptReference/WaitForEndOfFrame.html)の説明に基づく。一般の公式文書と、このゲームで実際に観測した動作の根拠は区別する。

実際の返却投影を既存ホストへリンクした15項目で、通常／切替後／座標付きのパス・URL・要求ID・未完成状態と、失敗結果の保持を確認する。旧ソースから忠実に抽出した投影では新しい要求ID保持検査が失敗する。これは描画キューやUnityのフレーム挙動のホスト試験ではない。

追加文言はPO4ファイルと現行3言語JSONを対応させ、`scripts/verify_screenshot_localization.py` で32件の正本・runtime・書式引数を検査する。暫定 `zh-hant.po` の訳文と既存runtimeの `zh-Hans` は別に保持する。

## 実機で確認した範囲

各版自身のDLL・固有ID・設定で、初回と通常再ロード後の4窓を照合した。通常・遅延中のカメラ移動・座標付き・配電／酸素の別フレーム・同名更新を計24撮影で確認し、実PNGと取得フレーム・カメラ・倍率・整数のシーン番号・nativeレイヤーID／ビュー名・時計・画像ハッシュ／サイズを照合した。予約時のAと撮影時のBを区別し、旧完成記録は同名更新後も撮影時情報を保持して現在の画像をchangedとした。

両IDの未ロード撮影は明確な翻訳済みエラーで、画像を作らない。撮影待ち中に通常メニューへ戻した各2件はgame_unavailableとなり、nullの撮影情報／画像と失敗状態を返した。通常ロード後に新しい要求IDで同じファイル名へ撮影でき、画像が存在しても旧IDの失敗は保持された。途中で利用者が停止中の速度を切り替えた1回は比較不一致として保存し、通常再ロードで元の6時計値へ戻った別窓を受入れた。失敗記録や比較条件を成功へ書き換えていない。

当時の実画像では外周の座標数値とグリッドを確認した一方、中央セルの座標文字は黒い背景のみになった。この描画は別課題として分離し、下記の[中央ラベル追補](#coordinate-cell-label-height)で限定修正した。requested_configurationを描画成功の根拠にしない。期限切れ・全キュー容量・未知レイヤー・描画停止・全解像度や他MOD全組合せの実機受入へは一般化しない。描画後の合成画面全体を単一のカメラ情報で保証するものでもない。

試験は停止を維持し、新規保存・時間進行・施工・DLC変更を行わず、通常終了後に元の導入物・設定・保存先選択・他MOD/DLCと開始時のゲーム未起動状態へ復帰した。個別の生応答・PNG・保存名・座標は公開文書に含めない。

## 追補: 中央セルの座標ラベルの高さ

中央セルのラベルだけ背景の高さが18pxで、共通の上下余白を除いた文字領域は16pxだった。外周と同じ高さ20pxへ揃えて文字領域を18pxにし、配置の中心を保つため上端の補正を−9pxから−10pxへ合わせた。変更は描画の1呼出だけで、幅・フォント・文字サイズ・省略設定・文字内容・セル選別・表示寿命・カメラ操作を保つ。新しいゲーム規則や状態操作は追加しない。

旧ソースの封印済み画像では中央が背景のみ、同じ範囲の修正後画像では完全なx,yが読めた。各版自身の参照ビルドと固有IDで、初回／通常再ロード後の4窓・計16画像を確認した。全表示、外周のみ、中央のみ、最後の表示から既存寿命を超えた後の消去を実PNGで読み、生成結果とは別に目視受入を記録した。時計・保護セーブ・カメラの復帰、元の導入物／設定／他MOD・DLC・選択先と開始時のゲーム未起動も照合した。

今回の可読性確認は日本語フォント・1920×1080・倍率6で、xとyがそれぞれ3桁の対象範囲に限定する。実フォントの内部metricsやoverflow分岐の実行は計測しておらず、他言語・DPI・解像度・長い座標文字列への普遍保証とはしない。TMPを模したホストや要求フラグによって可読性を補わず、描画の根拠は実際の画像とする。
