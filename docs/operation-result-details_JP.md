# opsの明示詳細結果を完全に保持する

子コマンドへ`detail=true`を明示した場合、`results[].result`に先頭テキスト結果を完全な文字列として返す。従来の12,000文字での切断が、子JSONを再解析できなくしていた。修正は詳細結果の代入だけで、JSONのobject/array/scalarや非JSONのテキストを勝手に変換しない。

`detail`省略とfalseは従来の要約を返す。親だけのdetail指定、エラー概要の上限、非JSON要約、確認・dryRun・単一コマンド制限は変更しない。取得量を抑える場合は、子コマンドのquery/limitを指定する。子自身が壊れたJSONを返した場合の修復、複数Contentの統合、他のbatch/地図経路は別範囲。

## 検証範囲

実ops実行・DSL解析・確認ポリシーをリンクしたホスト197条件が成功。長い各種JSONとUnicode・非JSON・短文・エラー、既定応答、確認・予行、入力非変更を含む。旧切断を戻す変異は完全一致検証で失敗した。ゲーム規則はホストのゲーム境界で代替しており、実機確認の代わりにはならない。

公開作業ツリーのホスト回帰とゲームDLL参照Compileを確認した。オンラインNuGet監査の接続失敗を受け、検査コマンドだけ`NuGetAudit=false`を指定した。リポジトリ設定の変更や依存脆弱性監査の成功を意味しない。

開発IDの実機40条件では長い研究・複製人間JSON、絞込との一致、通常応答の小ささ、停止と読取非変更を確認した。公開IDでの変更後実機受入は未実施。個別セーブ・実体ID・応答・ログ・クライアント設定は公開へ含めない。
