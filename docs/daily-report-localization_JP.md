# 日報の本体表示名とMCPエラーの言語

日報の `ReportGroup.stringKey` は本体の生成時に解決済みの表示本文であり、本体の見出し・項目行にも直接使われる。表示本文を `Strings.Get` へ再投入していたため、翻訳済みの名前に `MISSING` が付いていた。`name` へそのまま返し、生の `stringKey`、enumの `type`、context・notesを保持する。

独自の未初期化／該当日なしエラー2件だけをPO4／runtime3へ分離する。英語の既存文言、実行ID・引数・既定値・件数制限・filter・日付選択を保持し、MCPの言語変更でゲーム由来の名前を再翻訳しない。暫定Hant原本とHans runtime注記は別に維持する。

数値、丸め、単位、formatfn、既存の符号付きnegative値は変更しない。本体UIの親項目の平均化や符号表示との従来の差は、この名前修正とは別の範囲である。

## ホスト・原本対応

公開ソース自身の既存Coreへ実日報readerとLocalizerをリンクする回帰を追加した。既存16群を保った17群と、新規群の73 assertionsを確認した。旧公開reader全文も同じプロジェクトで正常コンパイルし、既存16群が通る一方、名前の意味条件で新規群が失敗する。試験で変更するprovider・native fixture状態はfinallyで復帰する。

ReportManager／Db／retirement／StringsとToolUtilの境界はhost fixtureであり、既定80／上限300の引渡しを実ToolUtilの解析試験とは扱わない。ゲームDLLをホスト実行していない。専用検査は独自エラー2件のPO4／runtime3対応だけを確認し、全翻訳の完成を主張しない。

## 公開版自身の実機確認

公開版自身の参照build.83は0警告・0エラー。選定13ファイルと全674参照入力のhashを前後照合し、専用2エラー検査と正式CLIの47カタログ群／298metadata／141埋込catalog／35選定PO context／6aliasが通過した。

公開DLLの読込元・専用IDと設定を確認し、停止分岐の同じ完結日の日報を英語・日本語・簡体字・autoで取得した。観測した見出しと内訳の全nameが解決済み本文と一致し、名前以外のJSONは修正前の基準と完全一致した。該当日なしのエラーも各MCP言語に追従し、全設定をautoへ戻して停止時計・速度・視野、保護した原本とチェックポイントの不変を照合した。MOD不一致は通常確認ボタンの予行と実行で確定し、停止を保った。

未初期化managerはhostだけの確認であり、その状態を実機で強制しない。全日付・全DLC・すべての本体レポートgroup、ブラウザー／PLib描画、ゲーム言語変更、本体UIの全数値表示との同等性を受け入れた意味ではない。生の日報、保存先、導入設定、実機ログ等の個別記録は含めない。
