# 予行の素材候補一覧を要求内で再利用する

`SelectElements` の明示素材・カテゴリ不一致の経路で、未在庫を含む同じ素材一覧を2度取得していた箇所を1度へ減らします。指定素材の照合と、拒否時に示す先頭20候補に同じ一覧を使います。最初の在庫あり一覧は従来どおり取得し、要求や配置地点をまたぐキャッシュは導入しません。

素材の一致順、先頭20件の順序、カテゴリ・autoの早期選択、未在庫・不足・未知・複数素材スロット・free-buildの判定と返却値は維持します。既存の「先の部分一致が後の完全一致より先に選ばれる」挙動もこの変更では修正しません。建材ルールや在庫数量の意味は変更せず、新しい文言や翻訳キーは追加していません。

## 実ソースでのホスト検査

`tests/OniMcp.BuildMaterialSelection.Tests` はMaterials全文、数量診断とJSON設定の実ソースをリンクします。native入力を固定した42ケース・482条件で、選択・候補・返却全文と入力の保持を確認します。旧Materials全文も同じ挙動条件を通し、最後の取得回数で失敗する負対照を使います。要求間で在庫・名前・発見資源が変われば次の取得へ反映するケースも含みます。

3素材・1カテゴリの固定入力では、対象経路の完全な一覧取得が3回から2回となり、在庫getterが9→6、発見getterが3→2、落下物列挙が12→8回です。旧・新で42ケースの全返却が一致することを別に比較します。これは実ソースに対するホスト入力境界の回数であり、ゲーム内のFPS・応答時間を測った結果ではありません。

既存BuildAvailabilityの541条件も確認しています。既存NativeUi試験にはBuildingAvailabilityReaderのリンク不足によるコンパイル失敗があり、変更前の隔離コピーでも再現しました。今回の実ソース回帰と本体参照ビルド、実機の読取結果とは区別して記録します。

## 範囲と残件

`placement_candidates` の返却limitは走査件数の上限ではありません。この小さな変更は全地点の走査や植生・設備の繰返し取得を上限化せず、過去の長時間待機の原因や解消を確定しません。実機は通常公開APIの名前指定 `planning preview` による1アンカーの読取を使い、素材の選択結果と停止時計・導入物・設定の保持を照合します。名前の解決自体はワールド内の設備等を列挙するため、検索の走査上限や正確な個体IDへの固定を確認した意味ではありません。建設の完成・運搬・通常UIでの配置可否、全DLC・全素材・任意の他MOD構成の受入へ一般化しません。親の予行TODOは開いたままです。

## 実機で確認した限定範囲

開発版・公開版それぞれ自身のDLLで、可視設備から確認したパイプ定義と2種類の適合素材を通常公開APIの名前指定で予行しました。明示した各素材の `materialSelection` は有効で、選択tagと正の既知在庫を返しました。完成済みの別素材パイプに対しては `existing_material_mismatch` で拒否し、建設・設計図を置きませんでした。autoは既設一致による素材選択前の早期終了だったため、選択処理の実機根拠へ数えません。公開版の固有設定先・所有パッチID・重複登録なしも実応答で照合しました。

停止時計6値、読み取れるカメラ値、設定ファイルの値とバイト列を保持し、保存・進行・区域登録は行っていません。通常終了後、導入物・設定・元の画像を控えへ照合して復元しました。通常bridgeの一時UI表示や通常ルール用の一時スコープは通るため、native内部キャッシュやUIの全状態が不変とは主張しません。

生座標を既存public引数へ渡した最初の試験は引数ガードで拒否され、素材選択へ到達していません。その失敗を保持し、クライアント向けに閉じられた内部coordinate経路は使わず、対応する名前指定previewで確認しました。これは未知素材の実機拒否、施工可否・完成・運搬、native取得回数や速度の計測を追加した意味ではありません。
