# 既存設計図の即時要求を本体UIへ渡す

既存Tile設計図が安全検査で自分自身に衝突する問題と、その先の削除・直接再生成を分けて対応します。安全検査の例外は確認済みの同一GameObjectだけへ限定し、既存設計図への即時要求は本体の建築ツールへ渡します。完成を強制するための削除・直接Build・source preview差替えへのfallbackは追加しません。

## 原因と対象範囲

旧検査は完成対象をignoredとして受け取りますが、その値が汎用の設備・設計図列挙へ伝わらず、対象自身を再び障害物として数えます。この自己競合と、別個体・別Prefab・端点の競合を混同しません。Prefab名・座標・返却辞書の文字列IDで一括除外しません。

本体BuildToolには既存blueprintをsourceとして渡す公開UI入口が見つかっていません。通常UIと同じpreview・配置検査を使い、一度の操作後に完成実体を独立確認します。本体が既存占有等で完成しない場合も、その結果を維持します。voidのTryBuild呼出だけから拒否理由や完成を断定しません。

初期の実行範囲は既存のTile設計図です。その他の既存設計図は明示的に未対応・利用不能として返し、旧直接再生成へ戻しません。既存の新規instant建設は変更対象外であり、その経路までUIへ移行済みとはしません。

## 要求と保護

既存の仮想地図編集、allowSandbox・instantBuild・confirmの条件と、停止・可視性・world・正確な形状・素材・向きの照合を維持します。通常予行や親の構文予行を本体UIによる完成検査へ格上げしません。

native呼出前と実行直前に対象を再確認します。UI未準備・他ツール使用・ドラッグ・モーダル・入力無効は利用不能/拒否とし、取得不能を正常へ補いません。自然固体・植物・Backwallを除去する経路は今回の入口で拒否します。地形許可や自動採掘を、この入口での即時除去許可へ読み替えません。

本体UIの操作を解除したことと、全選択や全UI状態が元へ戻ったことは区別します。対象以外のツール/状態を直接書き戻すfallbackは使いません。

## 結果の読み方

- 本体操作を試したこと、完成物が観測されたこと、元設計図が保持されたことを別々に返します。
- 正確な完成定義・向き・占有・登録状態・取得できる素材等が一致した場合だけ完成とします。欠測や別物の完成を成功にしません。
- 設計図が残ったままなら完成扱いにせず、そのIDと状態を維持します。既存の残留から「今回設計図を配置した」と推定しません。
- 例外や観測不能では変更を0と決めつけません。attempt回数からappliedやpartialを作らず、観測した変更と未知を保持します。
- 取得できないnative理由や全材料の検証、未知のUI形状を断定しません。自動再試行は行いません。

## ローカライズ

この経路の表示文16件は`Localization/po/onimcp.pot`と`en-us.po`・`ja-jp.po`・`zh-hant.po`を原文・訳文の管理元にします。stable contextは`OniMcp.MCP.BLUEPRINT_COMPLETION.*`、runtime keyは`blueprint_completion.*`です。既存ローダーへ合わせて`Catalogs/blueprint_completion.en.json`・`.ja.json`・`.zh-Hans.json`へ同じキーを保持します。簡体字runtime用の訳はPOコメントの`Runtime zh-Hans msgstr`から対応を照合し、暫定の繁体字訳を簡体字として読み替えません。ゲーム側の言語やStringsを変更しません。

実機試験は許可された試験分岐の停止中に行い、正確な対象設計図・同居配線・周囲セル・素材・接続・指示・時刻と取得可能なUI状態を前後比較します。成功/未完了は観測に従って受け入れ、試験を通すためにガードを緩めません。自然固体・植生等の未実施条件はホストと区別します。個別セーブ名・住民/設備ID・座標・生応答・設定・本体DLL/逆コンパイル内容は公開差分へ含めません。

関連する静的契約3本と素材ガードの既存13変異も成功しました。追加16キーのPO4種/runtime JSON3種、context・原文・placeholder・簡体字対応を照合済みです。総合ローカライズ検査は今回未変更の`game_control`引数定義を解析できず停止し、変更前HEADでも同じ失敗を確認しました。総合検査全体の成功とはしません。

開発IDのTile要求は`available=true`・`actionAttempted=true`・`uiRestored=true`、`completion_not_observed`・`applied=0`でした。自己競合のMCP safetyは通り、本体UIのvoid入口を一度呼んでも元の設計図が残りました。正確なnative拒否理由、実Tile完成の正例、全選択状態の復元は未確認です。同一のcanonical地図表記は変更なしとして子処理前に拒否されるため、その予行拒否を完成経路の証拠へ数えず、同一Prefabを指す許容済みID大小文字表記の新差分で子処理まで確認しました。

公開IDでも同じ5条件を通り、Tileの`completion_not_observed`と設計図保持・変更0・active tool解除を確認しました。実Tile完成・自然固体/植物/Backwallを伴う実行・全UI状態復元の実機証明とはしません。保護拒否や欠測分岐の追加範囲はホスト試験で確認しています。

元セーブを通常ロードして確認通知を閉じ、保存せず通常終了してから導入物を復元しました。これは今回の許可済み試験分岐と観測範囲の受入であり、全設備・他MOD組合せ・全世界の非変更を保証しません。個別のセーブ・座標・実ID・生応答・設定・ゲーム本体資料は公開差分に含めません。
