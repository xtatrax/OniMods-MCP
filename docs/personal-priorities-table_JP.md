# 個人優先度のMarkdown表

JSONに個人優先度の配列が含まれていても、Markdown表では複製人間の名前だけが表示される問題を修正した。従来の列生成と値抽出が配列形式を扱っていなかったために発生していた。

`priorities` 配列の `choreGroupId` を列の識別子とし、複製人間ごとの同じ作業グループの `priority` を表へ投影する。配列内の並び順や翻訳済みの表示名に値の対応を依存させない。

- 配列がある場合は、その配列を取得結果として扱う。空配列や欠損値を、別の項目や既定値で補完しない。
- `0`、負の値、明示的なnull、未取得をそのまま保持する。利用不可フラグから優先度を推測しない。
- 従来の辞書形式と平坦形式、最初に現れた列の順序、18列の表示上限を維持する。重複する作業グループは最初の観測値を採用する。
- 取得元のJSON、JSON形式での返却、ゲームの優先度設定操作は変更しない。

## 検証範囲

- ホスト検証: 配列順を変えた4人×16グループの全64値、0・負値・null・欠損、空配列、重複、旧形式、18列上限、入力の非変更を含む93条件が成功。既存の回帰検証も成功。初回はNuGet脆弱性情報の接続失敗を警告扱いのエラーとして停止したため、再実行時だけ`NuGetAudit=false`を指定してキャッシュ済み依存関係で確認した。リポジトリ設定は変更せず、オンライン脆弱性監査の成功は意味しない。
- 参照コンパイル: ゲーム同梱DLLを参照したCompileが成功（エラー0）。NuGet脆弱性情報の接続失敗によるNU1900警告2件を含む。
- 公開版のMOD識別子による実機検証: 未実施。ホスト検証や参照コンパイルだけでは、公開版の実機動作を確認したことにはならない。
- 開発版のMOD識別子による実機検証: 代表条件の実機161条件が成功した別記録として扱い、公開版の実機検証と区別する。個別記録は公開ツリーへ含めない。
