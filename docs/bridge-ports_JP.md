# ブリッジ端点と表示レイヤー

セルと地図のInfrastructure欄では、ブリッジのネットワーク種別に合う欄だけへ端点を表示する。複数設備が重なるセルも、代表設備1台だけでなくネイティブ占有一覧から対象ブリッジを選ぶ。

- 電力・自動化: UtilityNetworkLink.link1/link2を使用。
- 液体・気体・輸送: BuildingDef.UtilityInputOffset/UtilityOutputOffsetを使用。
- 建設予約: 完成プレハブの定義と、実際の予約の向き・基準点から計算。
- 完成設備: 実体のリンク定義と向き・基準点から計算。
- 欠測や境界外を中央座標で代用しない。bridgePorts=unavailableを返す。
- bridgeStateはplanned／complete、bridgePortSourceは取得元。bridgeConnection=not_evaluatedは、これが物理的な端点位置でありネットワーク接続や通電・流量の成立判定ではないことを示す。

## 検証

ホスト試験は実装本体NativeBridgeReadをスタブのゲーム型と組み合わせ、4回転×5ネットワーク×予約／完成、欠測、地図端の回り込み、別ワールド、不対象設備の85チェックを行う。ゲーム側API互換性は本体DLL参照ビルドで確認する。

開発版の実機では、建設予約の電線ブリッジ4方向・全12セル、既存完成設備の電力・液体・気体・輸送・自動化各1台・全15セルで、ネイティブ形状窓口の端点との一致と不関係な欄への非表示を確認した。完成設備には90°／180°／270°の実例を含む。既存設備は読み取りのみ。実際の通電・流量、全MOD設備、公開版固有IDでの実機動作を網羅する試験ではない。
