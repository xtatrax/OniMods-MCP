# 建設予行の検証範囲と受動読取

予行の受付は、本体の配置許可・施工完了・ネットワーク接続・実流量を保証しない。各経路は、実際に到達した段階を `validation` と対応する範囲情報に残す。既存の本文・エラー・操作ポリシーを保ち、欠測を成功や真0へ補わない。

| 経路 | 取得する範囲 | 含まない範囲 |
|---|---|---|
| map／opsの外側dryRun | 構文・許可された機能・解決できた占有形状 | 子の配置適合性・施工。子呼出0を明示する |
| .oniの建設・インフラ予行 | 実際に呼んだ子の配置予行と返された範囲 | 呼ばれていない子の成功 |
| 単地点・build_area | 現在の定義、素材、占有、対応した支持の観測 | 未対応の本体配置callback、将来の完工 |
| 既存実体の再利用 | 同一実体・座標・向き・素材に関する有限の照合 | 必要でない支持の評価を成功へ補うこと |
| placement_candidates | この呼出しで評価したアンカー窓 | 未走査領域・全矩形での最良候補・ページ間の原子的観測 |
| utility path／自動配線 | 実際に選択・予行・dispatchした範囲と子結果 | native drag未呼出の成功、通電・流量 |
| connect_existing | 正確な二対象の既存接続予行 | 予行時のUI操作・接続検証・流量 |
| テンプレート | 生成内容、呼び出した子と各子の結果 | 未実行の子、将来の共有世界状態のシミュレーション |
| 明示native UI preview（開発側のみ。公開版には追加しない） | 実際に要求した通常UI操作と観測状態 | 受動読取との同一視、利用不能時の直接状態操作による代替 |

`coverage=complete` は `validationScope` に示した有限の範囲だけを指す。構文検査や既存実体の同一性が完了しても、本体の全配置条件を検証済みとは読まない。未対応・未準備はunknown／partial／not_evaluatedを保ち、plainエラーでも本文を書き換えずmetadataへ範囲を残す。子の空応答や意味不明な成功らしい応答から完了を推定しない。

## 読取で条件を作らない

カタログ・素材・形状・候補・配置予行は、利用する既存の本体cacheを読む。Dbの遅延初期化、未知providerのcallback、未準備のresearch／permit／inventory状態を読取のために生成・更新しない。標準の既知getterも、調べた本体実装の範囲で利用する。未知MODのpropertyや任意のToStringを呼ぶカテゴリ探索は行わない。

読取だけの予行はInstant Buildや素材ルールを一時変更しない。要求したモードが現在の観測と合わなければ、配置適合性は未判別として返す。実行を承認した建設経路だけが局所的なmode scopeを持ち、内部予行・子実行後は元のmodeと要求を例外時も復元する。現状のモード観測と、ホストによるsetter呼出回数の証拠は別の根拠である。

候補検索では、同じ同期要求・同じ定義・世界・引数・free-build条件の窓に限り、availability／素材／外観と完成設備・設計図の列挙を再利用する。各アンカーの座標・占有・支持検査は残す。実行・条件不一致・次の要求は再取得する。共有可変リストを変更せず、実行へ予行結果cacheを持ち越さない。

## 候補数と未知

`limit` は返却行数、`maxEvaluations` は評価作業量、`maxCells` は要求矩形の大きさである。評価上限は既定64・最大256、矩形は最大2500、返却は最大50。`scanOffset`／`nextOffset` は同じ矩形の行優先位置を表す。未走査があれば全矩形の集計はnullとし、各ページの順位・件数だけを返す。

`validCount + rejectedCount = scannedAnchors` は既存のMCP予行boolean分類を保つ。rejectedには根拠不足による拒否も含むため、既知の不適合数は `knownRejectedCount` へ分ける。構造化された未知根拠から `unknownValid`／`unknownRejected` を数え、エラー文の文字列では判定しない。候補には絶対anchorと、指定時の相対座標情報を併記する。

## 同要求の計画支持

混在Prefabの地図要求は、対象を全て解決した後、支持となるグループを先に予行する。既知の1セルnative foundation定義・同じ世界・可視セル・有効な予行・実際のcommit予算に選ばれた支持だけを型付き要求内contextへ登録する。JSONや別要求から支持を注入できない。失敗・延期・採掘だけの床は支持にならない。

`planned_in_request` は物理床ではなく、完工を要する将来の依存関係である。既定の全体拒否では、一グループでもhard failureなら書込前に止める。実行は計画contextを渡さず、支持側の実操作後に本体の現物・設計図を読み直す。受付・部分実行・未完了を区別し、通常完工や全Tile familyへ一般化しない。

## 契約の境界

対象は、明示した経路のゲーム状態・既存native cacheを読取で製造／更新しないことと、実際の検証範囲を伝えることである。MCPの一時handle、局所allocation、純粋なdelegate cache、immutableな型／catalog初期化を含むプロセス全heapの不変性ではない。任意Harmony patch、未調査本体版・callback、外部スレッドの同時更新を保証しない。検査不能な条件を明示的な未知として扱う。

支持・地形への案内は現在のnative占有と支持定義に基づく。対象外採掘の過去全件の原因確定、通常施工の全完工、全接続familyの通電・実流量、他の診断・在庫・通常UI移行はそれぞれの課題に残る。

## 公開側の確認状況

公開ソース自身の実親・inline候補・dispatcher・serializerと固有fixtureを使う関連12ホストprojectを確認した。開発側専用レイヤー・native UI preview窓口を追加していない。共有型の追加に必要な未使用境界は、既存の公開側試験差を保って調整した。本体参照ビルドは0警告0エラー。独自25キーのPO4／runtime3対応100条件を通過し、暫定Hantと既存Hansを分離した。

公開版自身の導入DLL・専用設定先・版を確認し、停止実機で候補6窓、返却limit1／50と同じ64評価、明示予算・続き位置・終端と全矩形集計null、相対／絶対anchor、別world拒否、既存電線の反復再利用、特殊支持unknown、既定／非既定のnative unlocked外観を照合した。前後の400セル・6地図系統と抽出セル、時計・視点を保持した。外観の購入履歴やrarityは独立観測していない。

plan resolution、単地点・utility配置、テンプレート生成／子予行、ops構文のみの子0、未適用modeのunknown、未知操作拒否、.oniの実子予行と子1を確認した。自動配線OFFは未呼出、ONはselectionまで。sandbox地図指定は明示／省略の両方で既定予行・変更0を保持し、未対応予行のエラーmetadataも照合した。setter呼出回数とnative Instant ON入力の対称条件はhost根拠であり、停止実機の観測とは区別する。

混在要求は、支持なし・支持素材失敗・予算外支持・要求間漏れを実行前の全体拒否と変更0で確認した。通常予約の実行では計画支持とnative current falseを区別し、支持設計図の再取得、対象3セルだけの予約と周辺14セル保持を観測した。受付済みセルの完了は通常施工の完工・搬入・稼働ではない。

試験は保存せず通常終了し、元の開発版・停止セーブ・導入物・設定・保護データ・既存画像へ復帰して照合した。個別保存先・実体ID・座標・生応答・私有補助・開発履歴は公開差分に含めない。検証した経路の契約として受け入れ、他の配置family・全native getter・任意MODや全通常UIの成功へ一般化しない。
