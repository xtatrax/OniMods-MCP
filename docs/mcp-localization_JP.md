# OniMcp の言語切替

OniMcp 自身が生成する説明文を、ゲームの表示言語とは独立して選択できます。

| 設定値 | 表示言語 |
| --- | --- |
| `auto`（既定） | ゲームの言語に追従。未対応言語・取得失敗時は英語 |
| `en` | 英語 |
| `ja` | 日本語 |
| `zh-Hans` | 簡体字中国語 |

ブラウザーの `/settings/` にある「MCP の言語」で選択して保存します。MOD の PLib 設定の言語欄、または既存の `OniMcpConfig.json` の `Language` でも指定できます。JSON を編集する場合は他の設定を保持してください。古い設定ファイルには自動的に `auto` が適用されます。

設定画面から保存すると既存の設定保存処理に従って MCP サーバーが再起動します。JSON の手動編集後は設定の再読込が必要です。説明文をキャッシュするクライアントでは再接続してツール一覧を読み直してください。サーバーは `listChanged` 通知を新たに有効化していません。

`ja-JP` / `ja_JP` は `ja`、`zh-CN` / `zh_cn` / `zh_hans` / `zh_klei` は `zh-Hans` に正規化します。繁体字中国語を含む未対応の明示設定値は英語になります。Web 選択欄への不正な値の送信はエラーにします。

## 今回切り替わる範囲

- 公開7ツールの説明、引数説明、必須 `task` の説明。
- カタログの公開ツール要約・引数説明、対応する仮想操作ファイルのツール要約。説明検索は元の文章と選択言語の文章の両方を参照します。
- 中央ディスパッチの共通エラー、旧ツール名・別名の非推奨メッセージ。
- Web 設定画面のラベル・案内・入力エラー。

ゲーム由来の設備名・作業名・部屋名はゲーム側の翻訳を使用します。JSON キー、ツール名、action/domain、enum 値、Prefab ID、URI、地図の記号、SEARCH/REPLACE 文法、既存検索別名は切り替えません。

個別操作の結果文・エラー、リソース説明、仮想 Markdown 本文・凡例、既存 PLib 設定項目の多くは今後の移行対象です。すべての画面・応答の翻訳完了を意味しません。通常のトイレ使用を「お漏らし」と表示する問題など、状態判定を伴う課題はこの切替機構とは別に検証します。

## 翻訳の追加方法

`mods/OniMcp/Localization/Catalogs/` の JSON は、安定したキーと表示文の辞書です。`tools.*.json`、`settings.*.json`、`common.*.json` を同じキーで揃えます。選択言語にキーがない場合は英語、それもなければ呼出元の原文へ戻ります。

- 実行コードで組み立てた結果全体を文字列置換しないでください。翻訳する文を出力する箇所でキーを解決します。
- `{0}` などの書式引数、ID、コマンド例、単位、既定値、制限、安全条件は各言語で保持してください。
- `WorldEditorGeneratedGlyphData.cs` の元名称は記号の割当にも使います。表示翻訳のためにこの表を置換しないでください。
- カタログは DLL に組み込みます。`WithCulture=false` により別の言語別 DLL に分離せず、配布 ZIP でも利用できる構成です。
- スキーマは元の登録情報から複製して翻訳します。言語切替や取得側の書換えで、登録済み操作・キャッシュを変更しません。

検証コマンド:

```sh
python3 scripts/verify_mcp_localization_catalog.py --self-test
dotnet run --project tests/OniMcp.Config.Tests -c Release
dotnet run --project tests/OniMcp.Core.Tests -c Release
dotnet run --project tests/OniMcp.Tools.Tests -c Release
```

ホスト試験は設定・翻訳解決・スキーマ不変性を検証します。保存した `tools/list` 応答を `--tools-list <JSONファイル>` で渡すと、実際の公開引数とカタログの一致、各ツールの必須 `task` も照合できます。実機・画面操作の確認済み範囲は下記を参照してください。

## 分離の第一段階（2026-10-06）

ゲーム本体StreamingAssets/stringsとOxygenNotIncluded-JapaneseのPO構成を参考に、MCP独自文言とゲーム名称を区別した。全マップの案内・ボタン・エラー61項目をhuman-map.*.json、落下物詳細のラベル6項目をcell-details.*.jsonへ分離した。キー付き・領域別カタログとして既存3言語切替と英語フォールバックを使用する。PO変換や全応答の移行は今回の範囲に含めない。

HTMLは{{key}}をエスケープして解決、JSへはHTMLをエスケープしたJSON辞書を渡す。設定変更後はページを再読み込みする。カタログは既存どおりDLLへ埋め込み、外部翻訳パックの実行時読込はまだ行わない。

元素名はElement.name、設備名はネイティブ設備定義、作業名はGameUtil.GetChoreName/GetReportName、個体名はGetProperNameを使用する。翻訳プロジェクトのstrings.poをMCPへコピーしたり、ゲーム全体のStringsを書き換えたりしない。酸素レイヤーの凡例は公開ElementLoaderのゲーム名称を参照する。ゲーム言語とMCP言語を別にした場合、案内文とゲーム名称が別言語になるのはこの二系統の設計による。

ID・URI・座標・行順・単位・Prefab名・操作文法は変更しない。直書きのすべてが表示文ではないため、検索別名や地図記号をまとめて置換しない。残りの仮想Markdownや個別応答は段階的な移行対象。


検証: カタログ5群・15ファイルのキー整合、Config 15群（3言語テンプレート・辞書分離・HTMLエスケープを含む）、Tools 97件と関連回帰、ブラウザー相当のDOM代替試験3言語、実DLL参照Releaseビルド（警告0・エラー0）が成功。DOM試験では日本語のゲーム名・Oxygen IDを保持しながら、選択言語の案内・凡例・セル詳細・エラーを使用する。更新DLLを実ゲームへ配置し、実ブラウザー画面も確認済み（下記）。

ブラウザー相当試験: `node scripts/verify_human_map_localization.cjs`。Node.js以外の依存はなく、ゲーム／ブラウザーの実画面を代替する確認ではない。
