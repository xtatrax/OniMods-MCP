# 仮想操作の種子・栽培・研究一覧の返却

`ops/colony.md`の次の読取は、成功時に子ツールの`result`本文を既定で返します。件数だけで内容が取得できなかったため、既存の検索結果保持と同じ方式へ揃えました。

- `domain=bio bioDomain=farming action=seed_catalog`
- `domain=bio bioDomain=farming action=list_planting`
- `domain=management kind=research action=list`

既存のdomain・kind・action別名も同じ扱いです。正規の`colony_control`呼出を対象とするため、`ops/any.md`の`call tool=colony_control ...`でも保持します。別ファイルに書いたという理由だけで他のツールの返却を広げません。

## 情報量と実行の契約

本文は加工せず保持し、子の件数・空配列・未取得・ID・単位を補いません。`query`と`limit`を使って必要な項目を絞ってください。既定保持により実行回数が増えることはなく、ネイティブの読取・予行・書込を別のものへ差し替えません。

| 指定 | 返却 |
| --- | --- |
| `detail`なし | 対象三系統の成功本文を保持。引数のechoなし |
| JSON boolean `detail=false` | 本文と引数を省く既存の簡易返却 |
| JSON boolean `detail=true` | 既存どおり完全な本文／エラーと引数を保持 |
| 上記以外のコロニー操作 | 既定の簡易返却を維持 |

失敗時は既存の上限付きエラー本文を維持します。既定保持で全エラー本文まで展開することはありません。検索の`detail=brief|compact|full`は引き続き検索側の意味を保ちます。外側のworld_editorの`detail`と、操作行に書く子の`detail`は同一ではありません。

親の予行、未確認の実行、task不足、複数実行・座標・再帰操作の禁止条件は変えません。構文予行に成功しても子の読取結果を取得したという意味ではありません。

## 検証範囲

実ソースのoperation adapterとselectorを連結したホスト試験で、新規592条件と既存1726条件が通過しました。旧adapter全文と4種の意味変異は、コンパイル後の振舞い検査で失敗することを確認しました。子の取得内容は代替境界であり、本体のフィルターや栽培・研究の規則をホストで実行したという意味ではありません。対象案内1キーのPO4ファイル／runtime JSON3言語も照合しました。

ゲーム本体同梱DLLで参照ビルドした開発build.71は警告・エラー0で、配備DLL・ソース・実応答版を照合しました。実機79条件で、三系統それぞれの非空・一致検索・不一致の空結果、limit、既定本文と明示詳細の一致、falseの省略、別名・正規tool・非対象の簡易保持を確認しました。種子と栽培は既存resourceの同じ引数とも比較しています。研究一覧には専用resourceがないため、既存の明示詳細経路との比較です。約79KBの研究本文も完全に一致し、前後のゲーム時計・停止状態を保持しました。通常の未対応actionによる失敗も簡易表示を維持しています。本体例外や不正な子payloadは注入せず、ホストの範囲とします。

これは一覧の返却と観測時点の停止保持の受入です。栽培・研究の書込、全ゲーム状態・全native cacheの非変更は主張しません。公開側にもこの変更だけを選択適用し、公開ソースのホスト新規592・既存1726条件と、警告・エラー0の参照build.18を確認しました。公開固有IDの実機でも返却処理76条件が成功し、開発版の成功を代用せず同じ比較を実施しました。開発版の79条件には、必要だったMOD不一致の本体確認3条件が含まれます。公開版では対象画面がなく、その3条件の実行は不要でした。両版とも読取比較期間の時計を保持し、新規の例外ログはありません。

試験後は元の導入物・設定、原本と試験セーブ、共有保存領域、元の保存先選択とDLC設定へ復帰したことを照合しました。prefs全体を書き戻さず、通常起動によるSESSION_IDの変化を保持しています。全環境のバイト一致や最前面のメニュー描画を保証するものではありません。
