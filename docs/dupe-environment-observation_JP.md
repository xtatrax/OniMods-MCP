# 個体ごとの地図環境観測

通常ビューの非compact地図に出る環境観測を、可視のnative GameObjectごとに1項目へまとめる。同じ複製人間が上下の占有セルに登録されていても、名前を繰り返さない。表示形式は次の形を使用する。

```text
<native name> [id=<canonical ID or null>]: <native liquid name> @(X,Y), <cell mass>kg | <next contact>
```

| 情報 | 契約 |
| --- | --- |
| 個体の区別 | native GameObjectで集約。同じ名前・欠測ID・重複IDの別objectを統合しない |
| ID | 既存dupe窓口と同じKPrefabID.InstanceID。未取得はnull。グループ化のキーには使わない |
| 接触セル | 要求矩形内、可視かつactive world内で、本体のMinion登録と液体条件を満たすセルだけ |
| 液体と質量 | セルごとの本体名・座標・質量を保持。個体の質量にせず、合算しない |
| 順序 | 既存のY昇順・X昇順の最初の出現順。各個体内のセルも走査順を維持 |
| 既定の出力 | compactや別ビューへ補足を追加しない。空の観測の意味を変えない |

片側だけの矩形では、そのセルの観測だけを返す。アンカー・transformや全個体リストから表示外の体のセルを補完しない。液体条件は従来のIsLiquidかつ質量>0.01kgを維持し、表示は小数1桁。これは液体接触の観測で、移動・帰路・呼吸・危険度の診断ではない。

名前・IDは観測がある個体につき1回ずつ取得し、セル質量は合計しない。MCPの表示文はdupe_environment.empty／summary／dupe／contactの4キーを使用し、POのOniMcp.MCP.DUPE_ENVIRONMENT.*と実行JSON3言語を対応させる。本体名はゲームの言語を保ち、独立したMCP言語で翻訳し直さない。暫定zh-hant.poと既存zh-Hans実行文の分離を維持する。

## 検証と限界

公開側で既存MapRead610・トークン44・既存JSONビュー43・追加56条件、文言4キーのPO4／実行JSON3照合、ゲーム同梱DLL参照Compile（警告0／エラー0）が成功した。公開側の既存JSON地図のproduction linkと回帰を保持する。オンライン依存監査は実行単位で省略する。

開発IDでは代表2個体の液体接触と元セーブ復元を含む実機87条件が成功した。公開IDでの変更後実機受入は未実施であり、開発版の結果を公開版の実機確認とは扱わない。同名別個体・欠測／衝突ID・質量閾値・非表示セルはホスト試験の範囲。個別の名前・ID・座標、セーブ・応答・ログ・設定を含めない。水中危険・帰還安全の別TODOを完了したとはしない。
