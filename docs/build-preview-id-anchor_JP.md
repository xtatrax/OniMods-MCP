# 完成設備IDによる予行アンカー

`building_control domain=planning action=preview` の既存 `id` 引数を、完成設備の位置解決に使う。従来はIDが無視され、検索語なしではエラーになり、検索語があると別の設備を選び得た。変更は予行ハンドラーの呼出箇所と専用の読取resolverに限定する。

## 契約

- `id` がない場合は既存の位置解決へそのまま委譲する。名前検索の範囲・順序、既存の内部座標／区域互換経路は変えず、公開の座標操作を新たに許可しない。
- 明示IDはJSONの整数、Int32範囲、非0を要求する。文字列・小数・真偽値・null・配列・オブジェクトを整数へ読み替えない。構文不正の表示IDは `?` とする。
- 既存の完成設備登録から、geometryと同じ `KPrefabID.InstanceID`、なければUnityの `GetInstanceID()` を使う。KPrefabIDがある場合はUnity IDを別名として受け付けない。Unity由来の負IDは厳密一致なら使える。
- 同一IDの重複はワールドをまたいでも拒否する。対象不在、定義欠測、ロード中・登録未取得、不可視、無効セル、要求ワールド不一致も拒否し、名前や座標へフォールバックしない。
- 設備の本体参照セルを、新しい予行対象のlowerLeft入力として渡す。元設備の占有範囲の左下へ変換しない。既存offset適用後も範囲・可視性・ワールドを再検査する。公開スキーマへoffsetや座標引数を追加するものではない。
- 配置対象の `prefabId` とアンカー設備の種類は独立する。既存の素材・研究・支持・地形・占有等の予行判断を保持し、位置解決の成功を施工可能・建設完了と解釈しない。

エラー1キー `build.preview_anchor.unavailable` はPO原本4ファイルとruntime JSON3言語へ対応付ける。機械用の `invalid_id`／`not_found`／`ambiguous`／`unreadable` は翻訳しない。暫定HantのPOと既存Hansのruntime訳は分離する。

## 検証と限界

両版それぞれの実PreviewBuild・Anchorsの抽出と実TryPlanOne／既存アダプターを使い、新規359条件と既存253条件を確認した。旧Anchors・ActionPlacement全文への差替えもコンパイルし、IDだけを指定する最初の正例で失敗する負対照を確認した。query/area・本体geometry/material/UI等は明示fixtureで、公開middlewareや本体配置適格性の実行試験ではない。既存availability readerの不足リンクも実readerと入力fixtureで補い、従来の試験を緩めていない。

PO構文・文脈の一意性／対応・プレースホルダーと本体参照ビルドを確認した。両版それぞれ自身のDLLによる停止実機10条件で、IDだけの位置解決、競合queryよりIDの優先、別PrefabのWireの有効なdry-run、不在／不正型IDの拒否、IDなし名前指定を照合した。アンカーの現物geometry、6時計、報告カメラと設定を保持し、保存・時間進行・実施工・区域登録を要求せず、通常終了後に元の導入物・設定・保護セーブ・既存画像と未起動状態へ復帰した。公開固有の設定先と所有パッチIDも独立照合した。

背景壁が研究ロックされた例でも位置は解決され、施工可否は別に拒否された。背景壁の共存判定は今回の変更対象外で、本体通常UIとの照合は別に必要である。全予行の内部cache非変更、名前検索の全走査の上限、本体通常UIの同位置への配置、回転・全設備・全ワールドを受け入れたものではない。個別の実機証拠・保存先・対象ID・座標・環境設定と試験補助は含めない。
