# 建築案内の向きと座標

配置結果の `operationGuide` は、取得した配置情報の向きを予行テンプレートへ引き継ぎます。`orientationContext.source=placement` と `known=true` は、その配置で解決された向きであることを示します。

設備定義だけから返す汎用案内は配置情報を持ちません。`source=default_template` の `Neutral` はテンプレートの既定値で、設備の現在の向きを示しません。この場合は `known=false` です。解決済み配置情報の向きが未取得・不正な場合は予行テンプレートを返さず、`Neutral` に置き換えません。この説明は案内へ渡される配置メタデータを対象とします。要求文字列を向きへ解釈する既存の処理は変更していません。

`coordinateContext.anchor` は、地図パッチで設備の占有範囲の左下へ置くトークンの座標です。`nativeOrigin` は本体が使う基準セルであり、回転や設備定義によって両者が異なることがあります。取得した座標はそれぞれの役割のまま返し、案内側で再計算しません。`anchorSource=placement` は解決済み配置情報から来た座標を表し、元の要求を証明する値ではありません。

形状が未取得の場合は、`nativeOrigin` と `nativeOriginCell` を未取得のままにします。既存の外側の座標項目があっても、観測できた本体基準セルとして扱いません。

座標は参照用です。予行テンプレートは未完成で、座標だけを使って建築を実行できません。新しく読んだ地図の対象トークンを使ってパッチを用意し、予行後に別の確定要求を送る手順と、設備で許可される回転の確認が必要です。

検証範囲: 両版自身の配置モデルを結んだホスト試験で、3言語の案内・既知の向き・汎用テンプレート・未取得形状と不正な列挙値を照合した。旧モデル全文を同じ更新済みhelperへ結ぶ負対照は、コンパイル成功後に向きの保持条件で失敗することを確認した。共有helperを使う関連3系統のホスト試験、PO4とruntime JSON3、本体参照ビルドをそれぞれ確認した。

両版自身の停止実機で、同じ完成設備を基準にした4方向の通常読取予行（拒否結果の配置情報を含む）、独立した形状定義、相対オフセット、定義だけの汎用案内を照合した。対象設備の形状・停止時計・報告カメラを保持し、保存や建築を要求せず、元の導入物・設定・保護セーブ・既存画像と元の停止セーブへ復帰した。未取得形状・不正な列挙値と3言語すべての組合せはホストでの根拠であり、独立した実機再生成とは分ける。建築実行・搬入・完成、全設備定義や全native内部cacheの非変更へ一般化しない。個別の実機記録・保存先・対象ID・座標・私有補助は公開差分に含めない。
