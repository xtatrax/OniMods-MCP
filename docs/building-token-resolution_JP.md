# 設備トークンと未登録記号の検索

地図の設備トークンは完全Prefab ID、完全なゲーム表示名、一意な1文字記号の順に解決する。多文字の部分一致・誤記から先頭候補を選ばず、同名設備・共有記号は拒否する。既存処理を守る13条件を追加した。

生成記号にない設備も、明示した名前・IDによる通常ビューのmeaning_to_code検索で、読み込み済み本体定義を探せる。例: `world_editor command=symbols query=LogicPressureSensorGas direction=meaning_to_code matchMode=exact`。新しい行はsymbol=null/glyphAvailable=falseと本体のID・現在の表示名・未登録根拠を返す。完全IDの使用案内はローカライズする。記号の生成・登録や、建設可否の判定は行わない。

追加した読取はqueryのある通常ビューだけに限定し、空検索・逆引き・別ビューを拡張しない。既存の完全一致優先・件数・上限・登録済み別名とキャッシュ済み記号を保持する。欠損・例外はnativeDefinitionLookupのreadState/reasonCodesで区別し、partial/unavailable時の件数を全定義の不存在と解釈しない。新たな本体初期化・refreshは追加しない。既存の部屋記号処理は変更しない。

## 検証

公開作業ツリーでMapRead610条件、トークン44条件、既存JSONビュー43条件、実際の検索処理を連結した99条件と翻訳3キーの4PO/3実行JSON照合が成功した。開発側ではトークン3種と検索6種の誤実装を検出した。名前正規化・ネイティブ境界はホストの代替型であり、任意MODや全言語の証明ではない。

ゲームDLL参照Compileは警告0・エラー0。オンライン依存監査のみ実行単位で省略した。開発識別子の実機143条件では、ID/表示名/記号の解決、曖昧入力の拒否、梯子の通常予約と取消、記号未登録の気圧センサーと既存検索の維持、状態保持を確認した。予行は構文・形状の確認であり、全設備の配置・完成・搬入を検証したものではない。公開識別子を配備した変更後実機受入は未実施。

個別セーブ、現物のInstanceID、座標、ログ、画像、設定は公開内容に含めない。
