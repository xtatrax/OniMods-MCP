# Storage readback host regression

This console suite links the complete production StorageTools.cs, StorageTargetResolver.cs, StorageItemDetails.cs, StorageComponentDetails.cs, BuildingControlTools.cs, and McpJsonUtil.cs. It invokes the real hidden, legacy, aggregate and canonical storage handlers, then checks serialized JSON with the production serializer settings. No production method is extracted or copied into the fixture.

Run from the repository root:

```sh
rtk proxy dotnet run --project tests/OniMcp.StorageFilterReadback.Tests/OniMcp.StorageFilterReadback.Tests.csproj
```

The existing filter and item regressions remain in the same executable. They cover post-update native filter/mass readback, exact target guards, item identity, raw Kelvin and germ values, rounded Celsius, cached disease lookup, zero, native none index, missing/exception/nonfinite properties, independent failures, and compact list/write results. Canaries reject lazy Db.Get() initialization or writes to item properties during detail reads. Raw germ data does not assert treatment or safety.

The component regression distinguishes omitted/primary from all_components. Primary retains the existing item projection, including skipped null native entries and preserved duplicate references/order, and never enumerates or reads secondary Storage data. Explicit all_components enumerates concrete Storage components only on the selected GameObject, reports independent capacities, mass, visibility, native tag identity and raw filter order, and places items once in component rows. Component tags are not instance IDs: equal tags do not merge rows, and native Tag.Invalid is known unassigned without reading its Name or declaring partial failure. Successful native null filters remain raw null with native_null status, distinct from failed reads; they do not imply unrestricted acceptance. A valid unresolved tag and a failed tag read remain distinct.

The cases preserve observed zero/false/empty values, explicit nulls and reasons for unavailable fields, partial independent item results, and raw null item indexes in component rows. Invalid enumeration (null/throw/null slot/duplicate reference/missing primary) returns unknown component count and rows while preserving the independent primary summary. Child storages, neighboring objects and other IStorage implementations are excluded. Any explicit storageScope on list/filter writes, including null or invalid types, is rejected at every linked storage entry; non-storage canonical/aggregate domains reject it before unrelated dispatch.

A scope-free filter request still calls the selected GameObject's TreeFilterable.UpdateFilters once. The fixture allows that native callback to affect secondary contents/mass: the tests do not promise that the native method affects only one Storage. The adapter adds no per-component write loop and does not repair or deduplicate native contents.

StorageSourceRoot can select a private directory containing the four linked storage sources; CanonicalBuildingSource can select a private canonical router file. The component acceptance includes compilation followed by a failing behavioral assertion with the previous complete StorageTools.cs and the new helper linked but unused. Additional temporary source-copy mutations exercise default expansion, descendant inclusion, aggregate summary, raw-filter deduplication, unknown count normalized to zero, dropped null item slots, ignored write scope, Invalid tag treated as failure, explicit null scope silently defaulted, native null filters treated as failure, and primary selected by enumeration index. These runs do not modify product source.

The fixture substitutes Unity/component enumeration, native Storage fields and getters, PrimaryElement, Tag identity/name lookup, database caches, shared TreeFilterable behavior and unrelated sibling routes. Independently throwing fixture properties represent read boundaries; they do not establish that current native public fields themselves throw. It does not run Unity lifecycle, installed native getter internals, native TreeFilterable inventory effects, locale resolution, actual multi-component prefabs, pipe flow/germ simulation, or save/load. Those require separate runtime acceptance.
