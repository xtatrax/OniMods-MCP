# CycleTrim

Oxygen Not Included 向けの軽量なパフォーマンス改善 MOD です。CycleTrim は、頻繁に実行されるシミュレーション処理の一部を最適化し、原版と同じゲーム挙動を保ちながら処理負荷を減らします。

## 主な最適化

- 液体貯蔵庫・気体貯蔵庫からの、重複した自動化信号の送信を減らします。
- 拾得候補を検索したデータを再利用し、選択処理の負荷を減らします。
- 作業中の複製人間にだけ、負荷の高い更新処理の頻度制限を適用します。待機中の複製人間は応答性を維持します。
- 静止している動物の経路探索の頻度を制限します。

## 使い方

- 通常どおり購読し、有効にしてください。
- ほとんどの場合、追加設定は不要です。

## 互換性

- ゲーム本体と DLC のコンテンツに対応しています。
- 長期間進めているコロニーでも、既定では原版の挙動を維持する方針です。

## ベンチマークの概要

以下は条件を固定した場面での比較であり、すべての環境に当てはまるものではありません。ハードウェアやセーブデータによって結果は変わります。

| 場面 | 指標 | 変更前 → 変更後 | 改善 |
|---|---|---|---|
| 作業中の複製人間の頻度制限 | FPS 中央値（CPU の高負荷処理がある場面） | `70.6 → 85.1` | `+20.6%` |
| 作業中の複製人間の頻度制限 | Brain の合計処理時間 | `5.087s -> 2.449s` | `-51.9%` |
| 静止した動物の経路探索の頻度制限 | FPS 中央値 | `81.23 -> 109.28` | `+34.5%` |
| 静止した動物の経路探索の頻度制限 | Navigator の高負荷処理の合計時間 | `826.852ms -> 47.970ms` | `-94.2%` |
| UpdatePickups キャッシュ | ヒット率の中央値 | `24.37%` | 検索の `24.37%` がキャッシュにヒット |
| UpdatePickups キャッシュ | 平均処理時間 | `41.279us -> 35.708us` | `-13.5%` |
| UpdatePickups キャッシュ | 推定ヒット数/秒（30秒間の計測） | `~6.29 /s` | キャッシュヒットによる再利用 |

### Brain スケジューリングの関数単位の合成ベンチマーク（組み込み済み、通常の Creature のみ）

Brain の実行頻度制限は本番の Harmony パッチに組み込まれていますが、適用対象は原版の `CreatureBrainGroup` そのものだけです。複製人間とカスタムの Brain グループは、原版のスケジューリングを維持します。優先処理される Brain は、原版のキュー選択と即時実行の経路を維持し、通常の Creature 用の処理枠には算入されません。

> **これは単独実行の関数単位の合成ベンチマークであり、ゲーム内の FPS テストではありません。コロニー全体の性能へ直接換算することもできません。**

- 環境: 単独実行の `.NET 10` Release ベンチマーク。ONI は起動しません。
- 条件: 描画速度 `240` FPS を `30` 秒間シミュレートし、通常の Brain 呼び出し1回につき、決定的な CPU 処理を `512` 回繰り返します。
- 方法: `2` 回のウォームアップと、基準・変更後の測定順を交互に入れ替える `7` 組のペア測定を行います。中央値を報告し、すべてのサンプルで呼び出し回数とチェックサムの一致を確認します。
- 呼び出し回数: 合計は `43,200` から `19,200`（`-55.56%`）に減少しました。通常の Creature は `36,000` から `12,000`（`-66.67%`）に減少し、Dupe の `7,200` 回はすべて原版どおりでした。
- 代表的なローカル測定: 経過時間は `255.580ms` から `113.289ms`（`-55.67%`、`2.26x`）に減少しました。
- 対象範囲: 優先処理の負荷、実際の Sensors/PathProber の負荷、ゲーム内の Harmony スケジューリングの負荷は含みません。実際の FPS を示すものではありません。
- 安全面の違い: 現在のゲーム DLL は、動的な `i != brains.Count` をループの境界条件にしています。CycleTrim も毎回 Count を読み直し、更新中に追加された Brain を走査対象に含めます。ただし、リストが走査済みの位置より小さく縮んだ場合は終了し、原版の条件でループが終わらなくなる可能性を回避します。

### AsyncPathProber の重複排除と処理量の制御

- 原版の `CreaturePathFinderAbilities` そのものだけに対応します。Minion、Robot、カスタムの abilities は、動的な許可条件や装備の状態を完全に扱えると確認できないため、原版へフォールバックします。
- キャッシュは `Navigator.TakeResult` が正常に完了した後にだけ成立します。キューのクリア、登録解除、未適用・古い結果、例外ではキャッシュを完成させません。8回連続してスキップした後は、強制的に更新します。
- 起動時に、Creature の sentinel 回収が空のオーバーライドのままであることを検証します。ゲーム更新でこの前提条件が変わった場合、Async の最適化全体を無効にします。
- キューの処理枠は、ワーカー数と処理中の件数に応じて `1..4` の範囲で変わります。ワーカーが1つの場合、待機中は処理枠2、作業中は1です。
- 10,000リクエストの合成マトリクス（**ゲーム内 FPS ではありません**）: 目標ヒット率 `0/25/50/75/90%` に対して、PathProbe の実行回数は `10000/7701/5501/3301/2000`、回避した clone は `0/2299/4499/6699/8000` でした。理論上の探索処理の削減率は `0/22.99/44.99/66.99/80.00%` です。スキップ回数に上限を設けたフォールバックがあるため、実際の削減率は名目上のヒット率より低くなります。

再現用コマンド:

```bash
dotnet run --no-restore -c Release --project benchmarks/CycleTrim.BrainBenchmarks/CycleTrim.BrainBenchmarks.csproj
dotnet run --no-build --no-restore -c Release --project benchmarks/CycleTrim.BrainBenchmarks/CycleTrim.BrainBenchmarks.csproj -- --benchmark
```

`benchmark` スキルを使い、エージェントにベンチマーク全体を自動実行させ、標準化された JSON の結果を返させることもできます。

再現に必要な場面ごとの詳細は、[dist/CycleTrim/README.md](../../dist/CycleTrim/README.md) を参照してください。

## ソースコードの構成

```text
mods/CycleTrim/
├── ModInfo.cs          # KMod のエントリーポイント
├── Core/               # パッチ以外の中核ロジック（BrainRateCap など）
├── Patches/            # Harmony パッチ
├── docs/               # Steam 向け説明文
└── CycleTrim.csproj
```

このモノレポ内の他の MOD と同様、MOD のルートにはエントリーポイントとプロジェクト・メタデータファイルだけを置きます。パッチは `Patches/`、共通ロジックは `Core/` に置きます。
